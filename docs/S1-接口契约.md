# S1 跨模块接口契约文档（M03 BIM-GIS ↔ QGIS 插件 ↔ S2/S3/S4/S5）

> 版本: v1.0.0（基于 2026-07-15 之后的代码，含 #185 幂等键、#182 实测来源、机房字段）
> 维护人: S1 模块负责人（高）
> 范围: S1（通信工程智能辅助设计）对外的所有接口契约，是跨客户端 / 服务端 / 下游赛题的唯一权威定义。

---

## 0. 文档定位与受众

S1 是整条流水线（**设计 → 审查(S3) → 施工指令(S4) → 施工监管(S5)**）的**源头**：设计师在 GIS 环境中完成基站 / 机房 / 管线的参数化智能设计，产出可被 S3 审查、S4 转化的结构化设计成果。

本文档定义三类契约：

| 契约 | 方向 | 状态 | 说明 |
|------|------|------|------|
| **契约 A** | QGIS 插件 → M03 后端 | ✅ 已落地（权威定义） | 客户端↔服务端，本次补全为权威 Schema |
| **契约 B** | M03 后端 → Python 拓扑引擎 | ✅ 已落地（S1 内部） | 供运维 / 排障参考 |
| **契约 C** | S1(M03) → S2/S3/S4/S5 下游 | 🟡 待联调（推荐契约） | 设计成果交移，跨赛题 API |

> **重要**：S2/S3/S4/S5 当前多为骨架，尚未实际调用 S1。契约 C 为**推荐契约**，下游应按此结构实现消费侧；实战联调时可能微调（风险项 R-1）。

## 1. 通用约定

### 1.1 Base URL 与端口

| 服务 | 端口 | Base Path | 说明 |
|------|------|-----------|------|
| M03 后端（Spring Boot） | `8083` | `/api/m03` | 固定端口（避开 WorkBuddy 自身 3455） |
| Python 拓扑引擎（FastAPI） | `9001` | `/generate`、`/health` | S1 内部依赖，不对外暴露 |
| M03 前端（Vite dev） | `9000` | `/modules/m03/` | 仅开发态 |

生产/内网访问示例：`http://{host}:8083/api/m03/design/upload`

### 1.2 统一响应信封 `Result<T>`

所有 JSON 响应均为以下结构（来自 `packages/shared/backend/.../Result.java`）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { }
}
```

`code` 语义：

| code | 含义 | 客户端动作 |
|------|------|-----------|
| `200` | 成功 | 解析 `data` |
| `400` | 参数错误（含 Bean Validation 失败） | 不重试，提示用户修正入参 |
| `401` | 未认证 | 携带 / 刷新凭证后重试 |
| `403` | 禁止 | 终止，联系管理员 |
| `404` | 资源不存在 | 终止 |
| `500` | 服务器错误 / **限流** | 见 1.5 注意 |

**客户端判成功严格以 `code === 200` 为准**（QGIS `data_sync.py` 即如此判断）。

> ⚠️ **限流返回偏差（已知）**：限流耗尽时服务端返回 `code:500, message:"请求过于频繁，请稍后再试"`，**并非标准 429**。下游/客户端若对 5xx 做重试，会徒劳重试限流响应。契约建议服务端后续改为 429；在此之前，调用方应**识别 `message` 文案**而非仅看 code 来区分"真 5xx"与"限流 5xx"。

### 1.3 认证

| 端点族 | 当前鉴权 | 说明 |
|--------|----------|------|
| `/api/m03/design/**`、`/api/m03/project`、`/api/m03/region`、`/api/m03/model` | **内网免鉴权** | `application-shared.yml` 的 `security.permit-paths` 已放行，QGIS 裸 `requests` 可直调 |
| 其余（`/device` 等）及**跨赛题调用** | 需 JWT | `Authorization: Bearer <token>`（由 m01-auth 签发） |

> 公网暴露前必须将免鉴权接口改为 **API Key 或 IP 白名单**；当前内网放行仅适合局域网/本机。

### 1.4 幂等键与完整性校验

- **上传接口**要求请求体携带 `idempotencyKey`（QGIS 生成 UUID）。服务端查 `uk_scheme_idempotency` 唯一索引去重：重复键返回**已存在方案**（`dup=true`），不产生新方案、不翻倍写站点。
- **建议**（客户端应遵守、服务端后续将强制）：上传同时带 `X-Payload-Sha256` 请求头，值为请求体 JSON（按 key 排序、`ensure_ascii=False`）的 SHA256 十六进制串。当前服务端已记录该头但未强制校验，后续版本会校验并拒绝 `sha256` 不匹配的请求。

### 1.5 限流（RateLimitAspect，Guava 令牌桶）

| 接口 | 令牌桶（permits/sec） |
|------|----------------------|
| `/design/upload`、`/design/{id}/sites`（POST） | 10 |
| `/design/{id}/sites/measured` | 10 |
| `/design/{id}/sites/import`（CSV） | 5 |
| `/design/generate`、`/design/tasks/{id}/generate` | 5 |

超限返回 `code:500, message:"请求过于频繁，请稍后再试"`（见 1.2 注意）。生产默认开启（`rate-limit.enabled:true`），可通过配置关闭（测试环境用此开关）。

### 1.6 数据范围与校验规则（服务端强制，#185）

服务端 `DesignService.uploadDesignFull` 在写入前对每个站点做范围校验，越界站点**跳过写入**并计入 `skipped` / `errors`：

| 字段 | 合法范围 | 越界后果 |
|------|----------|----------|
| `longitude` | `[73, 135]`（中国陆地经度） | 跳过 |
| `latitude` | `[3, 54]`（中国陆地纬度） | 跳过 |
| `rsrp` | `[-140, 0]` dBm | 跳过 |

建议枚举（当前为自由字符串，契约建议下游按此收敛）：

- `siteType` ∈ `{MACRO, MICRO, INDOOR}`
- `scenario` ∈ `{URBAN, SUBURBAN, RURAL}`
- `roomType` ∈ `{汇聚机房, 核心机房, 接入机房}`（示例）
- `routeType` ∈ `{direct, manhattan}`（direct=直线路径，manhattan=曼哈顿路径）

实现位置：QGIS 插件 `design_engine/data_sync.py`（类 `DataSync`）。

### 2.1 端点清单（QGIS 实际调用）

| Method | Path | 用途 | QGIS 方法 | 限流 |
|--------|------|------|-----------|------|
| `POST` | `/api/m03/design/upload` | 原子上传完整设计方案（方案+站点+机房） | `upload_design` | 10 |
| `GET` | `/api/m03/design/{schemeId}/sites` | 校验回环：拉回站点比对数量与 siteId 集合 | `_verify_upload` | — |

### 2.2 上传请求体 `DesignData`（权威 Schema）

`POST /api/m03/design/upload`，`Content-Type: application/json`，建议带 `X-Payload-Sha256` 头。

```json

  "towerHeight": 35,
  "gridSize": "4x4",
  "totalSites": 3,
  "validSites": 3,
  "invalidSites": 0,
  "avgRsrp": -85.5,
  "routeType": "manhattan",
  "idempotencyKey": "3f1a...uuid",
  "sites": [
    {
      "siteId": "SITE-001",
      "siteName": "基站A",
      "longitude": 111.0,
      "latitude": 35.0,
      "towerHeight": 35,
      "siteType": "MACRO",
      "scenario": "URBAN",
      "rsrp": -82.3,
      "isValid": true,
      "invalidReason": ""
    }
  ],
  "machineRooms": [
    {
      "roomId": "ROOM-001",
      "name": "汇聚机房A",
      "longitude": 111.01,
      "latitude": 35.01,
      "roomType": "汇聚机房"
    }
  ],
  "deviceLayout": [ ]
}
```

**字段表（请求体）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `projectId` | Long | ✅ | 项目 ID（`@NotNull`） |
| `schemeName` | String | ✅ | 方案名称（`@NotBlank`） |
| `frequencyBand` | String | | 频段，如 `3.5GHz` |
| `towerHeight` | BigDecimal/number | | 塔高（米） |
| `gridSize` | String | | 网格大小，如 `4x4` |
| `totalSites` | Integer | | 客户端上报总站点数（用于计数对账） |
| `validSites` | Integer | | 有效站点数 |
| `invalidSites` | Integer | | 无效站点数 |
| `avgRsrp` | BigDecimal/number | | 平均 RSRP（dBm） |
| `routeType` | String | | `direct` / `manhattan`（QGIS 当前路由类型） |
| `idempotencyKey` | String | ✅（推荐） | UUID，服务端去重 |
| `sites` | List\<SiteData\> | ✅ | 站点列表（见下） |
| `machineRooms` | List\<Map\> | | 机房列表，元素：`roomId,name,longitude,latitude,roomType` |
| `deviceLayout` | List\<DevicePositionData\> | | 设备拓扑（来自 Python 拓扑引擎），可选 |

**`sites[].SiteData` 字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `siteId` | String | ✅ | 站点 ID（`@NotBlank`） |
| `siteName` | String | | 站点名称 |
| `longitude` | BigDecimal/number | | 经度（范围见 1.6） |
| `latitude` | BigDecimal/number | | 纬度（范围见 1.6） |
| `towerHeight` | BigDecimal/number | | 塔高（米） |
| `siteType` | String | | `MACRO`/`MICRO`/`INDOOR` |
| `scenario` | String | | `URBAN`/`SUBURBAN`/`RURAL` |
| `rsrp` | BigDecimal/number | | RSRP（dBm，范围见 1.6） |
| `isValid` | Boolean | | 是否通过避让校验 |
| `invalidReason` | String | | 无效原因 |

### 2.3 上传响应（`Result.data` = Map）

成功 `code:200`，`data` 为明细 Map（供 QGIS 校验回环）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `schemeId` | Long | 方案 ID（命中幂等键时为已存在方案 ID） |
| `dup` | Boolean | `true` 表示命中幂等键，返回已存在方案，未重复写 |
| `received` | int | 客户端上报 `totalSites` |
| `inserted` | int | 实际写入站点数（越界被 skip 的不计入） |
| `skipped` | int | 范围越界被跳过数 |
| `errors` | List\<{siteId,reason}\> | 被跳过站点的原因明细 |

> 校验回环（QGIS `_verify_upload`）：上传成功后 `GET /sites` 拉回，比对 `len(sites) == received` 且 `siteId` 集合一致，不一致仅告警、不影响上传结果。

### 2.4 客户端可靠性契约（QGIS `data_sync.py` 保证，#185）

| 保证 | 机制 |
|------|------|
| 不丢 | 上传前本地落盘 `~/.qgis_plugin_cache/upload_queue.json`，失败/中断保留，可重发 |
| 重试 | 指数退避 1s/3s/9s，最多 3 次；**仅** 5xx / 网络错误 / 超时重试，4xx 不重试 |
| 计数对账 | 发送前断言 `totalSites == len(sites)` 且 `validSites+invalidSites == totalSites` |
| 校验回环 | 上传后拉回 `GET /sites` 比对数量与 siteId 集合 |
| 幂等 | 每次生成 `idempotencyKey` UUID，服务端去重 |

## 4. 契约 C：S1(M03) → 下游 S2/S3/S4/S5 设计成果交移

S1 是流水线源头，下游按"**拉模式**"消费 S1 只读端点，或（未来）由 S1 在方案定稿后推送。本契约定义**下游应消费的数据视图**与**各下游职责**。

### 4.1 下游可消费的数据视图（推荐）

| 数据 | 获取方式 | 返回类型 |
|------|----------|----------|
| 设计方案 | `GET /api/m03/design/{projectId}` | `DesignScheme` |
| 站点清单 | `GET /api/m03/design/{schemeId}/sites` | `Site[]` |
| GeoJSON（几何/覆盖） | `GET /api/m03/design/{projectId}/geojson` | String(GeoJSON) |
| 设备拓扑 | `m03_device` 表 / 上传 `deviceLayout` | `Device[]` |
| 机房位置 | `DesignScheme.roomLongitude/roomLatitude/roomName` + 上传 `machineRooms` | — |

### 4.2 各下游职责与所需数据

| 下游 | 赛题 | 消费 S1 数据 | 产出 |
|------|------|--------------|------|
| **S2** | 多源异构工程数据融合（CAD） | GeoJSON / 站点几何 + 机房位置 | 与 CAD 图纸融合后的几何（可回填 M03 或独立存储） |
| **S3** | 基于行业标准的设计智能审查 | `DesignScheme` + `Site[]`（含 `rsrp`、`rsrpSource`、`isValid`） | 审查结论（问题清单 / 合规率 / 修订建议） |
| **S4** | 设计成果向施工指令自动转化 | `DesignScheme` + `Site[]` + `machineRooms` + `deviceLayout` | 物料清单(BOM) / 施工指令（对应 QGIS `bom_generator` 逻辑可迁移至此） |
| **S5** | 施工过程智能监管 | `DesignScheme` + `Site[]` + 设备位置（作为"设计基线"） | 与实际施工进度比对的监管结论 |

### 4.3 推荐的跨赛题调用契约（待联调落地）

| 项 | 约定 |
|----|------|
| 鉴权 | 下游持 m01-auth 签发的 JWT，`Authorization: Bearer <token>` |
| 关联键 | 下游以 `schemeId` + `projectId` 作为跨赛题关联键 |
| 数据格式 | JSON（UTF-8），时间字段 ISO-8601 |
| 版本 | 现状路径无 `/v1` 前缀；**未来统一加 `/v1`**，本文档以当前路径为准 |
| 推送（可选） | 方案定稿后可经消息队列 / Webhook 通知下游（当前未实现） |

> **风险 R-1**：S2–S5 后端当前为空壳，跨赛题联调未实战，接口契约可能需返工。各赛题有实质内容后统一联调。

## 6. 错误码与异常处理约定

- **Bean Validation 失败**：返回 `code:400`，`message` 为字段校验信息（如"项目ID不能为空"）。
- **资源不存在**：`code:404`，`message` 如"未找到设计方案"。
- **范围越界（#185）**：**不**返回错误，而是跳过该站点并在 upload 响应的 `skipped` / `errors` 中体现（保证"部分成功"而非整体失败）。
- **限流**：`code:500, message:"请求过于频繁，请稍后再试"`（见 1.2 注意）。
- **下游消费建议**：联调取数时，**优先用 `code` 判断成功**；对 `code:500` 需进一步比对 `message` 区分限流与真错误。

## 7. 版本与变更管理

- 本文档随 M03 后端代码演进；任何 endpoint / Schema 变更须同步更新本文档并 bump 版本号。
- **已知待修复偏差**（研发债，下游实现时需知晓）：

| 偏差 | 现状 | 建议 |
|------|------|------|
| 限流返回码 | `500` 而非 `429` | 改为 `429` + `Retry-After` |
| 路径版本 | 无 `/v1` 前缀 | 统一加 `/v1` |
| `X-Payload-Sha256` | 服务端未强制校验 | 后续强制校验，拒绝不匹配请求 |
| `siteType`/`scenario` | 自由字符串 | 收敛为枚举常量 |
| 跨赛题鉴权 | 内网免鉴权 | 公网改 API Key / IP 白名单 |
