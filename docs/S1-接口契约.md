## 1. 集成架构总览

```
S2~S5 子赛题  ──HTTP──>  M03 后端 (8083)  ──>  MySQL / 调 Python 拓扑引擎 (9001)
QGIS 插件     ──X-API-Key──>  M03 后端 (8083)   ← 生产者：把设计/站点/机房数据推上来
S1 Web 前端   ──JWT──>  M03 后端 (8083)          ← S1 自己的展示端（不对外暴露）
```

**关键结论**：S1 对外唯一的集成面是 **M03 后端 REST API（端口 8083）+ Python 拓扑引擎（端口 9001）**。
别队调「S1 的数据」= 调这些 REST 接口；**不要直接读库或连 QGIS**。

## 2. 基础信息

| 项 | 值 | 说明 |
|---|---|---|
| 后端 Base URL | `http://<host>:8083` | dev 默认 `http://localhost:8083` |
| API 前缀 | `/api/m03` | 所有接口以此为前缀 |
| 拓扑引擎 Base URL | `http://<host>:9001` | 配置项 `topology.engine.url`，默认 `http://localhost:9001` |
| 拓扑引擎超时 | `topology.engine.timeout-ms`，默认 5000ms | 不可达/超时时 M03 回退本地算法，返回结果可能不含 `coveragePolygons` |
| 当前环境 | 内网 / 未启用 HTTPS | 见「待补充」 |
| 速率限制 | 各接口独立 `@RateLimit`（见下表） | 超出返回 429 |

## 3. 统一响应格式 `Result<T>`

所有接口（除鉴权拒绝外）返回统一包络：

```json
{ "code": 200, "message": "操作成功", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `200` 成功；`400` 参数错误；`401` 未认证；`403` 无权限；`404` 资源不存在；`500` 服务器错误 |
| `message` | string | 提示文案 |
| `data` | T | 业务数据，结构见各接口「出参」 |

> ⚠️ **鉴权失败不走 `Result` 包络**：X-API-Key 缺失/错误直接返回原始 `{"code":401,"message":"Invalid or missing X-API-Key"}`；LLM 口返回 `{"code":401,"message":"Unauthorized: valid JWT or X-API-Key required"}`。

## 4. 鉴权（三档，最容易踩坑）

| 档位 | 适用路径 | 凭证 |
|---|---|---|
| **JWT（平台全局）** | `/api/m03/region`、`/api/m03/project`、`/api/m03/device`、`/api/m03/model`、`/api/m03/health` | 由 m01-auth 登录换取，请求头 `Authorization: Bearer <token>`（M03 自身不注册拦截器，由网关/共享 Filter 处理） |
| **X-API-Key** | `/api/m03/design/**` 全部方法 + `/api/m03/ftth/**` 的**写**操作 | 请求头 `X-API-Key: <key>`，值取配置 `m03.api-key` |
| **只读豁免** | `/api/m03/ftth/**` 的 **GET/HEAD** | 默认免 X-API-Key（配置 `m03.api-key-readonly-paths`，默认 `/api/m03/ftth`） |
| **LLM 双通道** | `/api/m03/llm/**` | `JWT` **或** `X-API-Key` 任一即可 |

> 🔴 **当前开发态默认密钥 = `CHANGE_ME`**。生产环境需换成团队共享密钥，并由 S1 owner 统一发放/轮换。
> 别队联调前，**先向 S1（高）申请 X-API-Key**，不要硬编码 `CHANGE_ME` 上线。

## 5. 接口清单

### 5.1 核心设计接口 `/api/m03/design`（全部需 X-API-Key）

| 方法 | 路径 | 入参 | 出参 | 限流 | 说明 |
|---|---|---|---|---|---|
| POST | `/upload` | `DesignData` (JSON) | `Result<Map>`（含去重/计数明细） | 10/s | **QGIS 插件原子上传**：机房 + 站点 + 设备拓扑 + 幂等键，一次提交 |
| GET | `/{projectId}` | path: projectId | `Result<DesignScheme>` | — | **核心读取**：方案 + 机房经纬度/名称/routeType |
| POST | `/{schemeId}/sites` | path: schemeId；body: `SiteData` | `Result<String>` | 10/s | 上传单个站点 |
| GET | `/{schemeId}/sites` | path: schemeId | `Result<List<Site>>` | — | 站点列表 |
| POST | `/{schemeId}/sites/measured` | path: schemeId；body: `List<SiteData>` | `Result<String>` | 10/s | 导入实测站点（强制 `rsrpSource=measured`，前端切换真值） |
| POST | `/{schemeId}/sites/import` | `multipart/form-data`，file 字段 | `Result<String>` | 5/s | CSV 导入实测站点（列见 SiteData 字段） |
| GET | `/{projectId}/geojson` | path: projectId | `Result<String>`（GeoJSON 文本） | — | **几何成果**，供 S5 数字孪生/三维渲染消费 |
| DELETE | `/{schemeId}` | path: schemeId | `Result<String>` | — | 删除方案 |
| POST | `/generate` | `GenerateRequest` (JSON) | `Result<DesignData>` | 5/s | 触发拓扑生成（转调 9001 引擎，失败回退本地） |
| GET | `/templates` | — | `Result<List<ParametricTemplate>>` | — | 参数化模板列表 |
| GET | `/templates/{templateId}` | path | `Result<ParametricTemplate>` | — | 模板详情 |
| POST | `/templates` | `ParametricTemplate` | `Result<String>` | — | 新建模板 |
| PUT | `/templates/{templateId}` | `ParametricTemplate` | `Result<String>` | — | 更新模板 |
| DELETE | `/templates/{templateId}` | path | `Result<String>` | — | 删除模板 |
| POST | `/tasks` | `DesignTask` | `Result<String>` | — | 创建设计任务 |

### 5.2 FTTH 数据接口 `/api/m03/ftth`（GET 只读免鉴权）

| 方法 | 路径 | 入参 | 出参 | 限流 | 说明 |
|---|---|---|---|---|---|
| GET | `/{tag}` | path: tag（数据集标识，如 `JAD-MAR-0001`） | `Result<Map<String,JsonNode>>` | — | **免鉴权**：返回该数据集全部分区（覆盖/楼栋/光缆等） |
| GET | `/{tag}/{type}` | path: tag, type | `Result<JsonNode>` | — | **免鉴权**：读取单个分区 |
| POST | `/{tag}` | body: JSON | `Result<Map<String,Object>>` | — | **需 X-API-Key**：上传/同步数据集 |

> FTTH 数据集结构（示例 tag `JAD-MAR-0001`）：`site`（PBO/BPE/PM 节点）、`boite`（箱体）、`imb`（楼栋）、`cable`（光缆，含 TRANSPORT/DISTRIBUTION/DROP）等 type。字段语义见 Ftth.vue / FtthMap.vue 的 humanize 函数。

### 5.3 Python 拓扑引擎（直连 9001，内网）

| 方法 | 路径 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| POST | `/generate` | `GenerateRequest`（snake_case，见 §6.6） | `TopologyGenerateResponse` | 站点布点 + 设备拓扑 + 覆盖多边形；M03 `/design/generate` 即转调此接口 |

> 别队一般**经 M03 `/design/generate` 间接调用**即可；直连 9001 仅在需要绕过 M03 编排时使用，且需在同一内网。

| id | Long | 方案 ID |
| projectId | Long | 所属项目 |

## 8. 调用时序（文字版，待架构师补 Mermaid）

**S1 上传并生成（典型链路）**
1. QGIS 插件 → `POST /api/m03/design/upload`（X-API-Key）→ M03 落库 + 幂等去重
2. 别队/前端 → `POST /api/m03/design/generate`（X-API-Key, GenerateRequest）
3. M03 → `POST 9001/generate`（snake_case 载荷）
4. 引擎 → `TopologyGenerateResponse`（sites + layout + coveragePolygons）
5. M03 失败回退本地算法（coveragePolygons 可能为 null）
6. 返回 `DesignData`；别队可 `GET /design/{projectId}` / `/geojson` 取数

**S5 消费几何成果**
- `GET /api/m03/design/{projectId}/geojson`（X-API-Key）→ GeoJSON → 三维渲染

## 9. 已知约束 / 注意事项

1. **design 口全要 X-API-Key**：包括 GET。只有 ftth 的 GET 豁免。别队常误以为"读也要 JWT"——实际 design 用 X-API-Key。
2. **幂等键**：`upload` 与 `sites` 上传均带 `idempotencyKey`（UUID），重复提交跳过不翻倍；QGIS 网络重试安全。
3. **本地回退**：拓扑引擎不可达时 M03 回退，结果可能缺 `coveragePolygons`，消费方需判空。
4. **限流**：生成类 5/s、上传类 10/s、LLM 2/s，超限 429。
5. **LLM 接口为预留**：参赛范围未实现语义审查，联调前确认是否启用。
6. **HTTPS 未启用**、**线上部署待核验**（见待补充）。
