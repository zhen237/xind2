## 一、环境要求

### 1.1 必须安装的软件

| 软件 | 版本要求 | 推荐版本 | 用途 |
|------|----------|----------|------|
| JDK | 21 | 21.0.11+ | 运行 Spring Boot 后端（采用 Java 21；编译目标 17，兼容 17/21 运行时） |
| Maven | 3.9+ | 3.9.16 | 构建后端项目 |
| Node.js | 18+ | 22.22 LTS | 运行前端项目 |
| MySQL | 8.0+ | 8.0.46+ | 数据库服务 |
| Redis | 6.2+ | 7.2.14 | 缓存服务 |
| Docker | 20.10+ | 24.x | 基础设施容器化（MySQL/Redis/MinIO/EMQX） |
| Git | 2.20+ | 2.40+ | 版本控制 |
| QGIS | 3.34+ | 3.44 LTR | QGIS 插件开发（仅 S1-高 需要） |

> Python 服务（m03-topology-engine / m07-cv-engine）使用 **Python 3.10**，详见各模块 README。

### 1.2 环境变量配置

```bash
# Windows (系统环境变量或 PowerShell Profile)
setx JAVA_HOME "C:\Program Files\Java\jdk-21"
setx MAVEN_HOME "C:\Program Files\Apache\maven-3.9.16"
setx NODE_HOME "C:\Program Files\nodejs"
# 将 %JAVA_HOME%\bin;%MAVEN_HOME%\bin;%NODE_HOME% 加入 PATH
```

```bash
# macOS / Linux
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export MAVEN_HOME=/opt/maven
export PATH=$JAVA_HOME/bin:$MAVEN_HOME/bin:$PATH
```

### 1.3 验证安装

```bash
java -version          # 期望输出: openjdk version "21.x.x"
mvn -v                 # 期望输出: Apache Maven 3.9.x
node -v                # 期望输出: v22.x.x
docker --version       # 期望输出: Docker version 24.x
git --version          # 期望输出: git version 2.x
```

## 三、启动基础设施（Docker）

### 3.1 一键启动

```bash
docker-compose up -d
```

这将启动 5 个基础设施服务：

| 服务 | 端口 | 用途 |
|------|------|------|
| MySQL | 3306 | 主数据库 (comm_platform) |
| Redis | 6379 | 缓存 |
| MinIO | 9000 / 9001 | 对象存储（文件/影像） |
| InfluxDB | 8086 | 时序数据库（M05 遥测） |
| EMQX | 1883 / 18083 | MQTT 消息代理（M05 设备数据） |

### 3.2 验证基础设施

```bash
# MySQL
docker exec -it xind2-mysql-1 mysql -uroot -pAdmin@123 -e "SELECT 1"

# Redis
docker exec -it xind2-redis-1 redis-cli ping
# 期望输出: PONG

# MinIO
curl http://localhost:9000/minio/health/live
# 期望输出: 200 OK
```

### 3.3 初始化数据库

```bash
# 执行初始化脚本（建库 + 建表 + 测试数据）
docker exec -i xind2-mysql-1 mysql -uroot -pAdmin@123 < scripts/init-mysql.sql
```

> 如果不使用 Docker MySQL，请手动创建数据库 `comm_platform` 后执行脚本：
> ```bash
> mysql -uroot -p < scripts/init-mysql.sql
> ```

## 四、配置环境变量

### 4.1 根目录环境变量

```bash
cp .env.example .env
```

编辑 `.env` 文件，根据实际情况修改密码：

```env

MYSQL_USER=root
MYSQL_PASSWORD=Admin@123          # 改为你的 MySQL 密码

JWT_SECRET=your-strong-random-secret-here  # 改为随机字符串
JWT_EXPIRATION=604800000

REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=

MINIO_ENDPOINT=http://localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin

MQTT_BROKER=tcp://localhost:1883
MQTT_USERNAME=admin
MQTT_PASSWORD=public
```

## 五、启动后端服务

## 八、启动 Python 服务（按需）

### 8.1 M03 拓扑引擎 (端口 9001)

> 重要：M03 后端的"智能辅助设计"（`/design/generate`）**优先调用本引擎**计算站点与设备 BOM；
> 引擎未启动时会静默回退到后端本地算法（输出一致但引擎的设备清单/覆盖分析不生效）。
> **演示前务必确认引擎已启动**，否则 S1"智能辅助设计"的产出无法体现。

推荐用随包启动脚本（自动建 venv + 装依赖 + 监听 127.0.0.1:9001）：

```bash
# Linux / Rocky 9.x（生产/VM）
cd packages/m03-topology-engine
nohup ./start.sh > topo_engine.log 2>&1 &

# Windows（本地开发）
cd packages/m03-topology-engine
.\start.ps1
```

手动方式（等价于脚本）：

```bash
cd packages/m03-topology-engine
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS/Linux
pip install -r requirements.txt
python main.py
```

验证：`curl http://127.0.0.1:9001/health` 应返回 `{"status":"ok","service":"topology-engine"}`。
M03 后端通过 `topology.engine.url`（`${TOPOLOGY_ENGINE_URL:http://localhost:9001}`）连接，同机默认即可。

### 8.2 M07 CV 引擎 (端口 8088)

```bash
cd packages/m07-cv-engine
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8088 --reload
```

> M07 当前为骨架，无实际代码。S5 开发时填充。

## 十二、常见问题

### 12.1 MySQL 连接失败

**现象**: 后端启动报 `Communications link failure`

**排查**:
1. 确认 Docker 容器在运行: `docker ps | grep mysql`
2. 确认端口未被占用: `netstat -an | findstr 3306`
3. 确认密码正确: 检查 `.env` 中的 `MYSQL_PASSWORD`
4. 重启容器: `docker-compose restart mysql`

### 12.2 端口冲突

**现象**: 启动报 `Port 8080 was already in use`

**排查**:
```bash
# 查找占用端口的进程
netstat -ano | findstr :8080
# 终止进程
taskkill /PID <PID> /F
```

各模块端口分配参见 [技术架构与开发规范.md](技术架构与开发规范.md) §1.2。

### 12.3 Flyway 迁移失败

**现象**: 后端启动报 `Flyway migration failed`

**排查**:
1. 检查 MySQL 中 `flyway_schema_history_mXX` 表是否有 `success=0` 的记录
2. 手动删除失败记录后重启: `DELETE FROM flyway_schema_history_mXX WHERE success=0;`
3. 确认 `scripts/init-mysql.sql` 已执行

### 12.4 Redis 连接失败

**现象**: 后端启动报 `Unable to connect to Redis`

**排查**:
1. 确认容器运行: `docker ps | grep redis`
2. 测试连接: `docker exec xind2-redis-1 redis-cli ping`
3. 检查 `.env` 中 `REDIS_HOST` 和 `REDIS_PORT`

### 12.5 前端启动失败

**现象**: `npm run dev` 报错

**解决**:
```bash
rm -rf node_modules package-lock.json
npm install
npm run dev
```

### 12.6 CORS 跨域错误

**现象**: 浏览器控制台报 `Access-Control-Allow-Origin`

**解决**: 各后端模块的 `WebConfig.java` 已配置 CORS。如仍有问题，检查 `allowedOrigins` 是否包含前端地址。

### 12.7 QGIS 插件不显示

**解决**:
1. 检查 `__init__.py` 文件是否存在
2. 清除 QGIS 缓存
3. 重启 QGIS
