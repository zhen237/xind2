# 本地部署指南（QGIS 端 + Web 端）

**版本**: 3.0（2026-09-16 全面重写）
**适用对象**: 零基础同学 / 新加入的队友（不需要看懂代码也能跑起来）
**环境**: Windows 10 / 11（macOS、Linux 的差异已在文中单独标注）

> 这份文档解决两件事：
> **① 在本地把 Web 端跑起来**（S1～S5 全平台）
> **② 在本地把 QGIS 插件装起来并出图**
>
> 写法是「照着做」：每一步都告诉你**怎么确认这一步成功了**。卡住了直接跳到 §9 故障速查。

---

## 0. 先读这 3 句话（很重要，能省你两小时）

1. **这套系统不是「起一个前端」就能用。** 你打开 S1 页面时，背后至少有 4 个东西必须在跑：MySQL、Redis、m01 认证服务、m03 设计服务。少了任何一个，页面要么转圈、要么报 401/500。
2. **数据库口令不写在这份文档里。** 因为代码仓库是公开的（任何人可见），口令写进来等于泄露。请**向组长索取**，他会告诉你填到哪个文件的哪一行（见 §2.4）。
3. **端口 3455 千万不要杀。** 那是你电脑上 WorkBuddy / 编辑器自己占的，跟本项目无关。同理，杀进程前务必先看清是哪个程序。

## 2. 前置准备

### 2.1 软件清单

| 软件 | 版本要求 | 用途 | 备注 |
|---|---|---|---|
| **JDK** | **21**（必须） | 跑 Java 后端 | 全项目统一 21，用 17 会出问题 |
| **Maven** | 3.9+ | 构建 Java 后端 | 团队统一路径 `D:\maven\apache-maven-3.9.16-bin\` |
| **Node.js** | 22 LTS | 跑前端 + S5 后端 | |
| **MySQL** | 8.0+ | 主数据库 | 库名固定 `comm_platform` |
| **Redis** | 5.0+ | 缓存（**必需**） | 少了它 m03 / s3 起不来 |
| **QGIS Desktop** | 3.44 LTR（最低 3.28） | 跑 QGIS 插件 | 只做 Web 端可以不装 |
| **Python** | 3.10+ | 跑 5 个 Python 引擎 | Web 端要用到 |

### 2.2 验证安装

打开 **Git Bash**（不是 CMD），逐条执行：

```bash
java -version     # 期望：openjdk version "21.x.x"
mvn -v            # 期望：Apache Maven 3.9.x
node -v           # 期望：v22.x.x
git --version     # 期望：git version 2.x
```

> **Maven 常见坑**：本机如果直接敲 `mvn` 报 `classworlds` 一类错误，就用完整路径
> `D:/maven/apache-maven-3.9.16-bin/bin/mvn.cmd`。下文所有 `mvn` 都可以换成它。

**MySQL 是否在跑**（Windows 上 MySQL 通常装成了系统服务）：

```bash
sc query MySQL80 | head -4     # 期望：STATE : 4  RUNNING
netstat -ano | grep ":3306"    # 期望：有 127.0.0.1:3306 LISTENING
```

如果 `STATE` 不是 `RUNNING`，用管理员权限执行 `net start MySQL80`。

### 2.3 拉代码

```bash
git clone https://github.com/zhen237/xind2.git
cd xind2
```

拉下来应该有这两个关键目录：
- `qgis-plugin/` —— QGIS 插件源码
- `packages/` —— 所有 Web 端模块（前后端）

> **注意**：下文所有命令都假设你的项目根目录是「你 clone 出来的那个 xind2 目录」。
> 如果你 clone 到 `D:\mycode\xind2`，把下文命令里的路径相应替换即可。

### 2.4 环境变量（`.env`）

后端要连数据库，必须填口令。**首次运行需要建这个文件**：

```bash
# 在项目根目录执行
cp packages/m03-bim-gis/backend/.env.example packages/m03-bim-gis/backend/.env
```

然后打开 `packages/m03-bim-gis/backend/.env`，把这两行改成真实值（**向组长要**）：

```env
MYSQL_USER=root
MYSQL_PASSWORD=改成组长的口令
```

`.env` 里其它键的含义：

| 键 | 说明 |
|---|---|
| `SERVER_PORT` | 后端端口。**除非端口冲突，否则不要动**（下面 §4 会讲一个例外：s2） |
| `MYSQL_URL` | 数据库连接串。默认连本机 `localhost:3306/comm_platform` |
| `JWT_SECRET` | 登录令牌密钥。本地随便填一串 32 位以上字符即可 |
| `JWT_EXPIRATION` | 令牌有效期（毫秒），保持默认 |

> 同一个口令要填给**每个需要连库的模块**（m01 / m03 / m04 / m05 / screen / s2 / s3 / s4）。
> 省事做法：把 `.env.example` 复制到各模块 `backend/.env`，口令填一样的。

## 3. 起基础设施：MySQL 与 Redis

### 3.1 MySQL

**不需要额外操作** —— 它是 Windows 服务，开机自启。
只需确认在跑（见 §2.2）。首次启动后端时，程序会**自动建表**（Flyway 迁移），你不用手工执行 SQL。

### 3.2 Redis（有坑，务必按这个来）

**推荐做法**：进入 Redis 所在目录，**不带任何参数**启动：

```bash
cd "D:/chrome/Redis-x64-5.0.14.1"
./redis-server.exe
```

保持这个窗口开着。看到 `Ready to accept connections` 就是成功了。

> **🔴 实测确认的坑**：Windows 版 Redis **如果传了一个不存在的配置文件，会直接启动失败**并报
> `Invalid argument during startup: Failed to open the .conf file`。
> 所以别学网上教程写 `redis-server.exe redis.windows.conf` —— 除非你当前就在 Redis 目录里。
>
> 验证是否起来了：另开一个窗口执行
> ```bash
> "D:/chrome/Redis-x64-5.0.14.1/redis-cli.exe" ping    # 期望：PONG
> ```

### 4.1 后端端口总表

| 模块 | 目录 | 端口 | 说明 |
|---|---|---|---|
| m01-auth | `packages/m01-auth/backend` | 8080 | 认证，**几乎所有页面都依赖它** |
| m03-bim-gis | `packages/m03-bim-gis/backend` | 8083 | S1 设计（核心） |
| m04-delivery | `packages/m04-delivery/backend` | 8084 | 交付 |
| m05-twin-ops | `packages/m05-twin-ops/backend` | 8085 | 数字孪生 |
| screen | `packages/screen/backend` | 8087 | 大屏 |
| s2-cad-fusion | `packages/s2-cad-fusion/backend` | **8096** | S2 融合。**yml 里默认是 8082，本地必须改成 8096**（见下） |
| s3-review-engine | `packages/s3-review-engine/backend` | 8089 | S3 审查 |
| s4-bom-transform | `packages/s4-bom-transform/backend` | 8090 | S4 清单 |
| s5-construction-monitor | `packages/s5-construction-monitor/backend` | 8091 | S5 监控。**这是 Node 写的，不是 Java**（见 §4.4） |

### 4.2 第一步：先构建 shared（第一次必做）

`shared` 是所有模块共用的公共库，**必须先装到本地仓库**，否则后面每个模块都编译不过：

```bash
cd packages/shared/backend
mvn install -DskipTests
```

看到 `BUILD SUCCESS` 即为成功。这一步只需做一次（除非有人改了 shared）。

> **🔴 铁律**：Maven **必须在模块自己的目录里执行**。
> 不要用 `mvn -f D:/xxx/pom.xml` 这种写法 —— 在本项目上会报「POM 不存在」或 `classworlds` 错误。

### 4.3 启动各个 Java 后端

**每个后端开一个终端窗口**（一共 8 个窗口，听起来多，但这样日志互不干扰、排查最方便）。

以 m03 为例：

```bash
cd packages/m03-bim-gis/backend
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8083"
```

其余模块同理，只改目录名和端口号。**s2 要特别注意**：

```bash
cd packages/s2-cad-fusion/backend
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8096"
```

> **为什么 s2 是 8096**：`s2` 的 `application.yml` 里默认端口是 8082，但这个端口在本机经常被别的东西占用（历史上踩过多次），所以**团队约定本地一律用 8096**。
> 前端的代理也已经指向 8096，你不用另外改前端。

**确认成功**：等启动日志出现 `Started XxxApplication in x.x seconds`，然后浏览器打开：

| 模块 | 验证地址 | 期望结果 |
|---|---|---|
| m03 | `http://localhost:8083/api/m03/health` | 响应体里含 `"status":"UP"` |
| m01 | `http://localhost:8080/api/m01/user` | **401 或 403** |

> **⚠️ m01 没有 health 接口**（它只有 `/api/m01/auth`、`/api/m01/menu`、`/api/m01/user` 三个控制器，也没引 actuator）。
> 所以验证 m01 的方式是：**能返回 401/403 就说明服务活着**；如果浏览器显示「无法访问」或返回 500，那才是没起来。

> **⚠️ 接口返回是「包了一层」的，别被吓到**：Java 后端统一用 `Result` 包装，长这样
> ```json
> {"code":200,"message":"操作成功","data":{"status":"UP","service":"m03-bim-gis","timestamp":1757...}}
> ```
> 所以 m03 health 看到的**不是**裸的 `{"status":"UP"}`。
> **更重要的**：业务出错时它可能返回 **HTTP 200 但 body 里 `code` 是 500**。
> 所以判断成功不能只看 HTTP 状态码，**要看 body 里的 `code` 是不是 200**。

> **看到 401 / 403 是正常的**，那是鉴权拦截，说明**服务活着**。
> 真正要警惕的是 **500**（服务内部报错）和 **打不开**（没起来）。
> 排查 500 的固定动作：去那个终端窗口里搜日志，找 `Unknown column` / `BadSqlGrammar` / `SQLSyntaxErrorException` 这几个关键字。

### 4.4 S5 后端不是 Java（容易踩）

`packages/s5-construction-monitor/backend` 是一个 **Node.js 项目**，没有 `pom.xml`，不能用 `mvn` 启动：

```bash
cd packages/s5-construction-monitor/backend
npm install
PORT=8091 node src/server.js
```

> **顺带说明 m07-cv-engine**：`packages/m07-cv-engine` 目前是**空骨架**（只有 `README.md` 和几个空目录，没有任何 `.py` 代码，也没有启动入口）。
> **它现在跑不起来，也不需要跑** —— 这是已知状态，不是你的环境坏了。

## 5. 起 Python 引擎（5 个）

### 5.1 为什么要给每个引擎单独建虚拟环境

5 个引擎对 Python 依赖的版本要求**互相冲突**（例如 s4 引擎要求 `fastapi` 低于 0.110，而 m03 / s3 锁定 0.115.0）。
装到同一个环境里必然有一个跑不起来。所以**一个引擎一个 `.venv`**，这是硬性要求。

### 5.2 引擎端口与启动命令

| 引擎 | 目录 | 端口 | 启动模块名 |
|---|---|---|---|
| s2 CAD 融合引擎 | `packages/s2-cad-fusion/engine` | 8092 | `cad_engine.server:app` |
| s3 规则引擎 | `packages/s3-review-engine/rules` | 8000 | `main:app` |
| s4 BOM 引擎 | `packages/s4-bom-transform/engine` | 8100 | `main:app` |
| **m03 拓扑引擎** | `packages/m03-topology-engine` | **9001** | `main:app` |
| m03 LLM 服务 | `packages/m03-llm-service` | 9002 | `main:app` |

以**拓扑引擎**为例（S1 最依赖它）：

```bash
cd packages/m03-topology-engine
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 9001
```

其余引擎：换目录、换端口、换模块名，其余命令完全一样。

> **不要用 `source .venv/bin/activate` 或 `.venv\Scripts\activate`**（尤其在脚本里 / 管理员权限下）——
> 有时它改了 shell 变量但 `python` 仍指向系统 Python，导致 `No module named uvicorn`。
> **直接写 `.venv/Scripts/python.exe -m uvicorn ...` 最稳。**

**确认成功**：

```bash
curl http://127.0.0.1:9001/health    # 期望 {"status":"ok","service":"topology-engine"}
```

|---|---|---|---|---|
| m06 门户 | `packages/m06-portal` | 5173 | `http://localhost:5173/` | `/` |
| **S1 设计** | `packages/m03-bim-gis/frontend` | **9000** | **`http://localhost:9000/modules/m03/`** | ★ `/modules/m03/` |
| m04 交付 | `packages/m04-delivery/frontend` | 5175 | `http://localhost:5175/` | `/` |

> **🔴 两个带星号的最容易踩**：m03 和 s3 的 `vite.config.js` 里设了 `base` 子路径（为了部署到服务器时挂在 `/modules/xxx/` 下）。
> 本地启动后**必须带上 `/modules/m03/` 或 `/modules/s3/` 这一段**才能打开。
> 只敲 `http://localhost:9000/` 会白屏 —— 不是坏了，是路径不对。

### 6.2 启动命令

```bash
cd packages/m03-bim-gis/frontend
npm install                                      # 第一次要几分钟
npm run dev -- --host 127.0.0.1
```

**关于 `--host 127.0.0.1`**：`vite.config.js` 里写的是 `host: 'localhost'`，在某些 Windows 环境下这只会绑到 IPv6 的 `::1`，导致 `127.0.0.1` 连不上、或者别的程序访问不到。加上 `--host 127.0.0.1` 最保险。

**注意**：`npm run dev` 启动后终端会打印一个地址。因为上表那两个模块有 `base` 子路径，**终端打印的地址通常不带子路径**，你得自己补上 `/modules/m03/`。

### 6.3 前端是怎么连到后端的

各前端目录下的 `vite.config.js` 里配了代理（proxy），你**不需要**手动改后端地址：

| 前端 | 代理 | 转发到 |
|---|---|---|
| m06 门户 | `/api/m01`、`/api/m03`、`/api/m04`、`/api/m05`、`/api/v1/s3` | 8080 / 8083 / 8084 / 8085 / 8089 |
| S1 (m03) | `/api/m03`、`/api/m01` | 8083 / 8080 |
| S2 | `/api/s2` | 8096 |
| S3 | `/api/v1/s3/review/*`、`/api/v1/s3`、`/api/m01` | 8000（规则引擎）/ 8089 / 8080 |
| S4 | `/api/s1`、`/api/s3`、`/api/s4`、`/api/s5`、`/api/pipeline` | 见其 `vite.config.js` |
| S5 | `/api/s5` | 8091 |

> **改完 `vite.config.js` 必须重启 dev server**（`Ctrl+C` 再 `npm run dev`），热更新不会重新加载代理配置。

## 7. QGIS 插件端

### 7.1 安装：用「链接」而不是「复制」（强烈建议）

QGIS 只会去它自己的插件目录里找插件：

```
C:\Users\<你的用户名>\AppData\Roaming\QGIS\QGIS3\profiles\default\python\plugins\
```

**推荐做法 —— 建一个目录链接（junction）指回仓库**，这样你改仓库里的代码，QGIS 那边立刻能看到，**永远不会出现「两份代码不一致」的怪问题**：

```bash
cmd //c mklink /J "C:\Users\<你的用户名>\AppData\Roaming\QGIS\QGIS3\profiles\default\python\plugins\qgis-plugin-complete" "D:\你的路径\xind2\qgis-plugin"
```

> **为什么不推荐复制**：仓库里有个 `scripts/sync-qgis-plugin.ps1` 是**复制**文件的，而且里面**硬编码了原作者的绝对路径**（`D:\homework\xind2\xind2` 和 `C:\Users\gao15\...`）。
> 直接跑它会把文件复制到一个你猜不到的位置。历史上的真实教训：开发目录和 QGIS 目录各存在一份，改了 A 却加载的是 B，排查了很久。
> **用 junction 就没这个问题。**

### 7.2 装依赖（装进 QGIS 自带的 Python，不是系统 Python）

插件部分功能依赖几个第三方库：

| 库 | 用途 |
|---|---|
| `dbfread` | 读取 Shapefile 的属性表（`.dbf`） |
| `pyshp`（`import shapefile`） | 读写 Shapefile |
| `numpy` | 热力图数值计算 |
| `requests` | 与后端同步数据 |

**关键点**：这些必须装到 **QGIS 自带的那个 Python** 里，装到系统 Python 是无效的。

从 QGIS 菜单打开 **插件 → Python 控制台**，粘贴执行：

```python
import subprocess, sys
subprocess.check_call([sys.executable, "-m", "pip", "install", "dbfread", "pyshp", "numpy", "requests"])
```

> 如果报 **`No module named pip`**（部分 QGIS 安装包不带 pip），先执行下面这句再重试上面的命令：
> ```python
> import ensurepip; ensurepip.bootstrap()
> ```

装完验证一下（还在同一个控制台里）：

```python
import dbfread, shapefile, numpy, requests
print("依赖 OK")
```

### 7.3 在 QGIS 里启用

1. 重启 QGIS Desktop
2. 菜单 **插件 → 管理和安装插件 → 已安装**
3. 勾选 **「通信基站智能设计平台」**（插件目录名是 `qgis-plugin-complete`）
4. 主界面上会出现插件面板

### 7.4 改完插件代码怎么让它生效

**只重启 QGIS 是不够的**（Python 会缓存已加载的模块）。正确顺序：

1. 在 QGIS 里 **插件 → 卸载插件**，再 **重新安装/启用**
2. 如果改了还是老行为，手动删掉缓存目录：
   ```
   C:\Users\<你的用户名>\AppData\Roaming\QGIS\QGIS3\profiles\default\python\plugins\qgis-plugin-complete\__pycache__
   ```
   以及各子目录（`ui/`、`layers/`、`tools/`、`design_engine/`）下的 `__pycache__`
3. 再重启用插件

### 7.5 底图：需要联网

插件的底图是**在线瓦片**（Esri 全球卫星影像 / OpenStreetMap / 天地图）。含义是：

- **断网状态下没有任何底图**，只能看到一个空地球 —— 这不是 bug。
- 部分内网/校园网可能连不上 Esri 或 OSM 的瓦片服务，表现为底图灰掉。
- 如果想用天地图，需要自己申请 token 并填到前端环境变量 `VITE_TIANDITU_TOKEN`（见 `packages/m03-bim-gis/frontend/.env.example`）。

### 7.6 插件与 Web 端是怎么连起来的

插件设计完成后，可以把成果**同步到 m03 后端**，然后就能在 S1 网页上看到。

插件读取这两个环境变量（在 `qgis-plugin/ui/design_dock.py:284`）：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `M03_API_URL` | `http://localhost:8083` | m03 后端地址。**默认就指向本机**，本地开发不用设置 |
| `M03_API_KEY` | 默认 `CHANGE_ME` | 内部接口鉴权密钥 |

所以本地联调的正常链路是：

```
QGIS 插件（设计 + 导出）──同步──▶ m03 后端 :8083 ──▶ S1 网页 :9000/modules/m03/
```

**前提**：m03 后端必须在跑。插件同步失败时，弹窗会告诉你它在连哪个地址，先核对那个地址是不是 `http://localhost:8083`。

### 7.7 插件的主要能力（方便你判断「装好了没」）

- **引导式工作流**：左侧面板是一步步的向导（基站选址 → 参数 → 覆盖 → 管线 → 机房 → 报表 → 导出），能看到步骤指示器就说明插件加载成功
- **FTTH 光网络设计**：支持加载真实 FTTH 数据、做覆盖缺口识别与建议站点
- **导出**：当前视图 PDF、CAD 图纸（DXF）、标准工程图册（三视图，标注 GB 51456-2023）、工程报表（Excel）、BOM 清单
- **覆盖热力图**：按 RSRP 分级渲染

### 8.1 逐项自检清单

全部跑起来后，逐条勾：

| # | 检查项 | 命令 / 操作 | 通过标准 |
|---|---|---|---|
| 1 | MySQL | `sc query MySQL80` | STATE = RUNNING |
| 2 | Redis | `redis-cli.exe ping` | PONG |
| 3 | m01 后端 | `http://localhost:8080/api/m01/user` | **401 / 403**（有响应即存活；m01 无 health 接口） |
| 4 | m03 后端 | `http://localhost:8083/api/m03/health` | body 里含 `"status":"UP"` 且 `code=200` |
| 5 | 拓扑引擎 | `http://127.0.0.1:9001/health` | `{"status":"ok",...}` |

> **口令不在文档里**，同 §2.4 向组长索取。

### 8.2 端到端走一遍（最有说服力的验证）

1. 打开 `http://localhost:5173/`，用 `admin` 登录 → 进入门户
2. 从门户进入 **S1 智能设计**
3. 打开一个已有设计任务（或新建一个），点「查看成果」
4. 地图上应该出现**基站点位 + 机房点位 + 连线**

**期望结果**：如果用团队共享的摩洛哥样例数据（文件名 `design_20260913.geojson`，向组长索取），你应该看到 **6 个基站**，以及 **6 个机房**（每个机房在自己的基站正下方）。

### 8.3 ⚠️ 两种「看着对、其实不对」

这是本项目最容易误判的地方，**排查问题时先排除这两种**：

**情况一：拓扑引擎没起，系统偷偷用了后备算法**

现象：设计任务能跑、页面也有结果，但产出跟预期不一样（例如本该是真实的 6 个站点，结果变成一片规则网格）。
原因：后端连不上引擎时会**静默回退**到本地算法，只在日志里留一行警告，不弹错。
排查：确认 `http://127.0.0.1:9001/health` 是通的；去 m03 后端日志搜「回退」/「degraded」。

**情况二：浏览器里存着旧草稿，把真实数据顶掉了**

现象：明明改了数据，页面刷新后还是老的（例如显示一堆和当前项目无关的点）。
原因：S1 页面会把编辑状态存在浏览器 localStorage（键名 `m03_ai_design_draft`），重新打开时**自动恢复草稿**，看起来像是数据没更新。
排查：在页面里点「清除」，或按 F12 → Application → Local Storage → 删掉 `m03_ai_design_draft`，然后**硬刷新**（`Ctrl + F5`）。

## 9. 故障速查（按现象查）

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| 后端启动就挂，日志有 `Unable to connect to Redis` | Redis 没起 | 按 §3.2 启动。注意别传不存在的 conf 文件 |
| 后端启动报 `Communications link failure` | MySQL 没起 / 口令错 | §2.2 确认服务在跑；核对 `.env` 里的 `MYSQL_PASSWORD` |
| 后端启动报缺 `JwtUtils` 之类 bean | 该模块的启动类没排除/没扫描到共享安全配置 | 这是代码层面的已知问题，问组长；m04/m05/s2/screen 与 m01/m03/s3 的处理方式不同 |
| 页面能开，但接口全 401 / 403 | 鉴权拦截。**这是正常的**，代表服务活着 | 需要登录拿 token。S1 的 `/api/m03/design/**` 还需要请求头 `X-API-Key`（本地默认值 `CHANGE_ME`） |
| 接口返回 **500** | 服务内部报错 | 去后端终端搜 `Unknown column` / `BadSqlGrammar`；本项目最常见的原因是**实体字段和数据库列对不上** |
| 接口 HTTP 状态是 200，但页面还是报错 | 业务错误被包在 body 里了（`code` 不为 200） | **别只看 HTTP 状态码**，F12 看响应体里的 `code` 和 `message` |
| 打开 `http://localhost:9000/` 白屏 | 少了 `base` 子路径 | 地址改成 `http://localhost:9000/modules/m03/`。s3 同理要带 `/modules/s3/` |
| 前端能开，但所有接口请求失败 | 对应的后端没起，或代理目标不对 | 对照 §6.3 的代理表，把缺的后端补起来 |
| 改了 `vite.config.js` 不生效 | 代理配置只在启动时读一次 | 重启 dev server |
| 端口被占用（`Port 8080 was already in use`） | 别的程序或上一次没退干净的进程占着 | `netstat -ano \| grep ":8080"` 找到 PID，确认是残留进程再 `taskkill /PID <PID> /F`。**⚠️ 看到 3455 千万别杀，那是 WorkBuddy 自己** |
| `mvn` 报 `classworlds` 错误 / POM 不存在 | 用 `-f` 指路径了，或 `mvn` 不在 PATH | 用 `cd` 进模块目录再执行；或用完整路径 `D:/maven/apache-maven-3.9.16-bin/bin/mvn.cmd` |
| s2 前端连不上后端 | s2 后端没改成 8096 | 启动时加 `--server.port=8096`（§4.3） |
| 引擎启动报 `No module named uvicorn` | 用了 `activate` 但 python 还是系统的 | 直接用 `.venv/Scripts/python.exe -m uvicorn ...`（§5.2） |
| QGIS 里看不到插件 | 目录链接没建对 / 插件没勾选 | §7.1 检查链接是否存在；§7.3 检查插件是否勾选；必要时删 `__pycache__` |
| QGIS 插件报缺 `dbfread` / `shapefile` | 依赖装到系统 Python 了 | 按 §7.2 装到 QGIS 自带 Python |
| 插件改完代码没变化 | Python 模块缓存 | §7.4：卸载→重装插件 + 清 `__pycache__` |
| QGIS 地图没有底图 | 底图是在线瓦片，断网/被墙 | 联网即可（§7.5） |
| 上传自己的 GeoJSON 后站点全没了 | 上传接口**只接受中国境内坐标**（经度 73–135、纬度 3–54）。境外坐标会被静默跳过 | 走「建任务 + 灌入本地数据」的方式，不要走上传接口。或者先把坐标转到中国境内做演示 |
| 数据库/表结构相关的一切报错 | Flyway 迁移没跑或跑错了 | 确认各模块 `application.yml` 里有 `baseline-version: 0`；`flyway_schema_history_<模块>` 表里不该出现 `type=BASELINE` 的版本（那代表该版本实际没执行） |

**如果窗口已经关了，进程还占着端口**：

```bash
# 先查是谁占着（把 8083 换成你要查的端口）
netstat -ano | grep ":8083"

# 确认是残留的 java/node 进程后，按 PID 结束
taskkill /PID <上面查到的PID> /F
```

```bash
netstat -ano | grep LISTENING | grep -E ":(8080|8083|8084|8085|8087|8089|8090|8091|8096|8000|8092|8100|9001|9002|5173|5175|5182|5189|5190|5191|9000)\b"
```

## 12. 已知的脚本局限（用之前先看这段）

仓库里有一个一键脚本**已经入库**，另有一个**还没入库**，两个都**带有原作者机器的绝对路径**，别人 clone 后不能直接用：

| 脚本 | 是否已入库 | 问题 | 建议 |
|---|---|---|---|
| `scripts/sync-qgis-plugin.ps1` | ✅ 已入库 | ① 硬编码源目录 `D:\homework\xind2\xind2\qgis-plugin`；② 是**复制**而非目录链接，容易造成两份代码不一致 | 用 §7.1 的 junction 方式，**不要用这个脚本** |
| `scripts/start-all-demo.sh` | ❌ **未入库**（只存在于原作者本机，clone 拿不到） | ① 顶部写死了 `D:/homework/xind2/xind2`、`C:/Users/...` 等路径；② 启动 Redis 时用的是**相对路径** `redis.windows.conf`，从仓库根目录运行时该文件不存在，**Redis 会启动失败**（实测报 `Failed to open the .conf file`） | 在它被修好并入库之前，请按 §3～§6 逐项手动启动 —— 更稳，也更容易定位问题 |

> 如果你手里正好有这个 `start-all-demo.sh`：想用就先改顶部那几个变量，并把 Redis 那行改成绝对路径（或先 `cd` 进 Redis 目录再执行）。
