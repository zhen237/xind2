## 附录 C：直接喂给 AI 的一键提示词（复制到 WorkBuddy）

> 用法：把下面整块提示词复制进 WorkBuddy 对话框，**把 `<>` 里的三个变量改成你自己的**，然后发送。AI 会按步骤执行。

```
你是我的 S5 开发助手。当前工作空间是仓库根目录 `xind2`。

我的任务：把本地 C# 孪生后端项目上传到仓库的 S5 模块，并基于它生成 Vue 前端页面。

请你按以下步骤执行。每完成一步，简要汇报结果，再继续下一步。如果遇到不确定或需要我确认的事，先问我再做，不要自己猜。

【我的配置】
- 我的 C# 项目本地路径：<在这里填你的路径，例如 D:\李\s5-csharp>
- 目标分支：<在这里填你的 S5 分支名，例如 feat/s5-twin-csharp>
- C# 后端端口：<建议填 8092，避免冲突>

【执行步骤】

第 1 步：准备分支
- 确认当前在仓库 `xind2` 根目录。
- 检查本地是否存在分支 `<目标分支>`，没有就从 `origin/main` 新建它。
- 切换到 `<目标分支>`。

第 2 步：上传并规范 C# 后端
- 读取我本地 C# 项目路径 `<C#路径>`，判断哪些是该项目的文件（.sln、.csproj、src、配置文件等）。
- 把这些文件复制到 `packages/s5-construction-monitor/twin-csharp/`。
- 检查并做以下规范对齐：
  * 接口 Controller 路径统一为 `/api/s5/...`
  * 配置 CORS，允许前端 http://localhost:5191 调用
  * 设备/告警/孪生状态实体字段，对齐 `packages/m05-twin-ops/backend` 里的 Device.java 和 Alert.java 字段命名与类型
  * 在 `packages/s5-construction-monitor/twin-csharp/README.md` 里写清：怎么启动、监听端口 `<后端端口>`、Swagger 地址、依赖（.NET 版本、数据库等）
- 把变更提交到本地 `<目标分支>`，commit message 为 `feat(s5): 新增 C# 孪生后端`。
- 推送到远程 `<目标分支>`（不要合并到 main）。

第 3 步：生成前端页面
- 在 `packages/s5-construction-monitor/frontend/` 从零搭 Vite + Vue3 + Element Plus 工程，参考 `packages/m06-portal` 的依赖版本和风格。
- `package.json` 端口脚本为 5191，`vite.config.js` 配 `/api/s5` 代理到 http://localhost:<后端端口>。
- 读取 `twin-csharp/` 里的 C# 接口，生成三个页面：
  1. 施工监测看板
  2. 设备孪生状态页
  3. 告警列表页
- 页面必须真实调用后端接口，禁止写死 mock 数据。
- 提交到本地 `<目标分支>` 并推送到远程，commit message 为 `feat(s5): 生成 5191 前端页面`。

第 4 步：本地运行检查
- 按 `twin-csharp/README.md` 启动 C# 后端。
- 在 `packages/s5-construction-monitor/frontend/` 执行 `npm install && npm run dev`。
- 检查 http://localhost:5191 是否能打开三个页面，且数据是从后端真实拉取的。
- 如果运行失败，给出错误信息并建议修复方案；不要合并到 main。

第 5 步：汇报
- 完成后告诉我：C# 文件是否已上传到 `twin-csharp/`、前端是否已生成并跑通、当前分支状态、是否有遗留问题。
- 最后提醒：合进 main 由高出面统一处理，你不要自己合。

【约束】
- 只动 `packages/s5-construction-monitor/` 目录，不动 m01/m03/m05/m06 等他人模块。
- 不要往 `main` 分支 push，不要自己开 PR 合 main。
- C# 后端作为独立服务运行，不塞进 S5 的 Java 空壳。
- 所有接口前缀 `/api/s5/`，不要自创前缀。
- 字段对齐 m05 的 Device/Alert 实体。

【注意】
- 推送到远程前，先确认你有 GitHub 写入权限（登录/SSH 已配好）。如果 push 因权限失败，告诉我具体错误，不要重复尝试。
- 如果 `<C#路径>` 不存在或为空，先停下来告诉我，不要继续。
```

> 这个提示词把整份手册的要点压缩成 AI 能直接执行的指令。你不需要手动 git add / commit / push，AI 会按步骤帮你做。**前提是你已经装好 WorkBuddy 和 .NET SDK，并且能 clone 仓库。**
