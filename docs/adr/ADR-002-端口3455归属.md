# ADR-002 · 端口 3455 归属（WorkBuddy 自身）

> **状态**：已采纳（Accepted）
> **日期**：项目早期（铁律）
> **决策人**：高（统筹）
> **相关**：`docs/立项书.md` §6 约束、`docs/术语表.md` 端口速查

---

## 背景（Context）

开发环境使用 **WorkBuddy**（AI 开发 IDE），其自身服务占用 **3455 端口**。

历史上出现过两次事故：
1. 误将 3455 当作某个业务后端服务，在启动后端时抢占该端口导致冲突。
2. 在批量清理进程时误 `kill` 3455，导致 WorkBuddy IDE 功能异常。

根本原因：端口分配表未把 3455 纳入说明，团队不清楚它是 IDE 自身而非业务端口。

---

## 决策（Decision）

**端口 3455 是 WorkBuddy 自身，不是任何业务服务。**

- 业务后端启动务必显式指定端口：`--server.port=8083`（或各自分配端口），**绝不**使用 3455。
- 启动脚本如需清空环境变量，先 `SERVER_PORT=` 再启动，避免回退到 3455。
- **绝对不要 kill 3455 进程**（除非明确要关闭 WorkBuddy 本身）。
- 端口分配表与脚本模板中显式标注 3455 为「WorkBuddy 自身，禁止占用」。

---

## 替代方案（Options Considered）

| 方案 | 结论 |
|------|------|
| 业务服务使用 3455 | ❌ 否决：与 IDE 冲突，必崩 |
| 修改 WorkBuddy 监听端口 | ❌ 不现实：IDE 内置，不可随意改 |
| **业务规避 3455 + 写入铁律（采纳）** | ✅ 零成本，靠纪律规避 |

---

## 后果（Consequences）

**正面**
- 彻底避免误杀 IDE / 端口冲突。
- 纳入端口表后新人一眼可见。

**负面 / 注意**
- 依赖团队记忆与文档约定，需在 onboarding 与脚本模板中反复强调。
