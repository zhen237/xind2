# ADR-001 · 全模块统一 JDK 21

> **状态**：已采纳（Accepted）
> **日期**：2026-07（项目初始化阶段）
> **决策人**：高（统筹）
> **相关**：`docs/立项书.md` §6 约束

---

## 背景（Context）

项目包含 11 个 Java 模块（m01/m03/m04/m05/m06/m07/s2/s3/s4/s5/shared）。初版部分模块使用 JDK 17，另一些未显式锁定版本，导致：

- 本地与 CI 构建环境 JVM 版本不一致，出现依赖编译/运行不兼容。
- Spring Boot 3.x 最低要求 17，但团队希望锁定一个长期支持版本以避免后续反复升级。

---

## 决策（Decision）

**全 11 个 Java 模块统一 `<java.version>21`，明确禁止 JDK 17。**

- 本机仅安装 **Eclipse Temurin 21**。
- Maven 使用项目固定路径（避免系统 `mvn` 类世界 classpath 报错）。
- 任何新建 Java 模块必须继承同一父 POM 的 21 设定。

---

## 替代方案（Options Considered）

| 方案 | 结论 |
|------|------|
| 保留 17 与 21 混用 | ❌ 否决：增加 CI 复杂度，跨模块依赖易踩坑 |
| 升级到 22 / 23 | ❌ 否决：非 LTS，团队不追新特性 |
| **统一 21（采纳）** | ✅ LTS、构建一致、支持到 2030s |

---

## 后果（Consequences）

**正面**
- 构建与运行环境一致，消除 JVM 版本漂移。
- 获得 LTS 长期支持与较新语言特性。

**负面 / 注意**
- 个别老旧依赖需升级以兼容 21（已在初始化阶段处理）。
- 新成员环境必须装 21，否则无法启动。
