**原始需求复述（唯一需求来源，不增不改）**：

> 「在 qgis 插件中我想新增一个功能：补盲补热的功能，发现覆盖薄弱的区域，如何新增一个站点，如何完成选址，布线，材料清单等等后续流程。」

即需在现有插件内串起一条**线性可演示链路**：

```
发现覆盖薄弱区域 → 新增站点 → 选址（落点） → 布线 → 材料清单
```

**已锁定的四条口径（不可更改，本 PRD 不再讨论）**：

1. **补盲对象 = 只做蜂窝基站**（不做 FTTH；插件内蜂窝基站与 FTTH 是两套独立模型）。
2. **弱覆盖判定 = RSRP 栅格阈值法**（复用插件现有 Okumura-Hata + RSRP 栅格计算；栅格上连续低于阈值的区域 = 弱覆盖区。**不引入** MR / MDT / 路测数据）。
3. **落点 = 插件内闭环**（识别 → 建议站 → 采纳 → 布线 → 清单全部在 QGIS 内完成，**不推送 M03 后端、不落库**）。
4. **材料清单 = 复用插件现有 BOM 能力**（不引入 S4 的 `material_catalog.json` 物料字典，不新写土建工程量）。

## 1. 产品目标

- **G1｜把被删除的能力以新形态加回流程**：原第③步「覆盖缺口识别」已被删除（见 `design_dock.py:783-784` 注释）。本次以**蜂窝 RSRP 栅格弱覆盖诊断**的形态把它加回，形成"诊断 → 建议站"的可视化环节。
- **G2｜打通"从弱覆盖到物料清单"的端到端闭环**：在同一插件内完成 弱覆盖区识别 → 建议站点 → 采纳为正式站 → 站点级 BOM 输出，全程不依赖后端与外部字典。
- **G3｜让落点与参数"可解释"**：建议站位置、建议覆盖半径、聚类粒度均由可说明的物理量（频段 / 制式基线 / RSRP 阈值）驱动，便于评委追问时逐项解释，而非黑盒输出。

**演示目标（硬性）**：上述链路要能在答辩现场 **3 分钟内讲清并演示完**（识别 → 建议 → 采纳 → 布线 → 清单），流程线性、无跳转、无等待后端。

## 2. 定位说明（重要）

⚠️ **命题书未要求"补盲补热"。** 对官方赛题 PDF 全文检索 `补盲 / 补热 / 弱覆盖 / 盲区 / 站址 / 选址 / 站间距 / 链路预算 / 覆盖半径` 均 **0 命中**；命题书对"覆盖"的唯一要求是「审查覆盖率 ≥ 80%」，指的是**审查体系的覆盖面**，与无线覆盖无关。

**因此本功能定位 = 自选亮点功能，不是赛题硬指标。** 由此推导出的方案取舍原则：

- **优先"能演示、算法可解释"**，不追求工程完备性；
- 允许使用示意 / 待校准参数，但必须显式标注，不得伪装成实测值；
- 范围从严裁剪，宁可少做，不可拖垮现有"现网补盲"演示的稳定性。

## 3. 用户故事

- **US1**｜作为 S1 设计工程师，我希望能在地图上**直观看到当前站点集合的弱覆盖区域**，以便判断哪些地方需要补站，而不是靠经验猜。
- **US2**｜作为 S1 设计工程师，我希望插件对每一片弱覆盖区**给出建议站坐标与需求评分**，以便我快速得到候补站点而不是手工取点。
- **US3**｜作为 S1 设计工程师，我希望**一键把建议站采纳为正式站点**（进入站点表、出现在地图上），以便继续走后续设计与出图流程。
- **US4**｜作为 S1 设计工程师，我希望采纳后的站点能**直接生成布线路径与站点级材料清单（BOM）**，以便交付设计与概算。
- **US5**｜作为 S1 设计工程师，我希望弱覆盖判定阈值与制式（4G/5G）**可在面板上调**，以便针对不同频段/制式演示不同结果。

### P0 — 最小可演示闭环（必做）

## 5. 交互设计

### 5.1 建议：以"独立步骤"形态把「覆盖缺口识别」加回流程

现有流程为 **7 步**（① 环境·底图 `:1215` ② FTTH现网 `:1276` ③ 设计区域 `:1347` ④ 基站参数 `:1399` ⑤ 生成布局 `:1555` ⑥ 管线·场景 `:1621` ⑦ 出图·交付 `:1833`）。

**建议：在 ⑤ 生成布局 之后，恢复一个独立步骤「弱覆盖诊断·补站」**（原⑥⑦ 顺延为⑦⑧），而不是并入第⑤步。

理由：

1. **诊断对象在第⑤步才存在** —— 第④步「基站参数」**只设参数、不产生站点**；站点由第⑤步「生成基站布局」按钮产出（`_build_step6:1555` → `_generate_layout:5632`）。若插在④⑤之间，点诊断时 `generated_sites` 为空，RSRP 栅格全是 `-200` 哨兵值，**图上会显示"整片区域都是盲区"**，诊断无对象。
2. **演示叙事更真实**：变成"设参数 → 生成初版布局 → 发现还漏 → 补站 → 拉线 → 出图"，符合真实工程设计流程（先排一版，再查漏补缺）。
3. **布线零成本**：补的站先于第⑥步「管线·场景」进站点池，用户到该步点「生成管线」即被自动拉线（`_generate_pipelines:3662` 遍历站点池）。
4. **利于参数化**：阈值、制式、聚类粒度都挂在这一步的参数区，边界清晰。

**备选（降级方案）**：若评审担心新增步骤牵动步骤编号 / 引导文案（`_update_guidance:1125-1155`）/ 页映射（`:844-852`）改动面，可降级为**第⑤步内的一个分组面板**（不作为独立步），演示叙事稍弱但改动面更小。**默认按"独立步骤"实施。**

> ⚠️ **2026-09-19 修正**：本节 v1.0 原文写的是"在 ④ 基站参数 与 ⑤ 生成布局 之间"，**该位置是错的**（理由见上第 1 条）。已修正为"在 ⑤ 生成布局 之后"。修正后附带好处：第⑤步的硬索引恰好不变，需改索引的原有步骤从 3 个减到 **2 个**（⑥管线·场景、⑦出图·交付）。

### 5.2 面板元素（在第④步之后的新步骤内）

- **参数区**
  - 制式下拉（4G LTE / 5G NR(Sub-6) / 5G NR(mmWave) / 4G+5G 协同）—— 取值驱动覆盖半径与聚类粒度；
  - 弱覆盖阈值输入（RSRP，dBm，可调）—— 默认沿用插件现有"覆盖达标"口径（≥ -80 dBm 为达标，低于该值判弱），最终取值见 §8 待确认；
  - 聚类网格尺寸 / 最小栅格数（可调）—— 控制聚类颗粒度，避免碎片噪声；
  - 按钮：**「覆盖诊断」**（生成栅格 + 提取弱覆盖区）、**「生成建议站」**（聚类并出建议站图层）。
- **结果表：建议站点表**（与现有站点表并列展示，不混入）
  - 列：建议站编号 / 经度 / 纬度 / 需求评分 / 建议覆盖半径(km) / 制式 / 聚类栅格数；
  - 行操作：**「采纳」**（写入 `generated_sites`）、「定位」、「删除」。
- **状态回显**：诊断完成后，回显"弱覆盖区 N 个 / 建议站 M 个 / 当前站点覆盖率 X%"（X% 复用 `calculate_coverage_rate`，仅展示口径，不编造提升幅度）。

### 5.3 地图图层

| 图层 | 内容 | 复用点 |
|------|------|--------|
| RSRP 连续热力栅格 | 连续色带，色带中已有"弱覆盖/盲区"档 | `design_engine/coverage_renderer.py`（`RSRP_COLOR_STOPS:12`）、`coverage_heatmap.py:86/143`、`layers/coverage_layer.py:11` |

### 5.4 关键数据流与"硬坑"提示（给架构师）

- **站点数据两套 schema 并行**：`models/site.py:8 @dataclass Site`（字段：site_id/name/longitude/latitude/site_type/tower_type/tower_height/mount_type/scenario/status/tech_generation/coverage_radius/capacity/antennas）与 UI 实际使用的**裸 dict**（`design_dock.py:2427-2444`、`2485-2499`；字段：band/frequency/power/gain/num_sectors/tech_generation/capacity/coverage_radius）。二者字段不一致，转换点在 `_show_bom_dialog:6541`、`_export_report_xlsx:4422`。**采纳建议站时必须两侧同时补字段**，否则 BOM/导出处会缺项。
- **覆盖半径列**：站点表已有「覆盖半径(km)」列（`:2057, :6515`），现值 = 站间距 × 1.5（`:6498`）；本次建议站的"建议覆盖半径"应优先取制式基线（见 §9），并与该列口径对齐。
- **聚类骨架参考而非照搬**：`ftth/coverage_gap.py` 是 **FTTH 场景**（判断 ZNRO/ZPM 覆盖不到 IMB 楼栋），**不能直接照搬**；本次仅参考其算法骨架（400m 网格聚类、需求评分结构、建议站图层）与交互形态，**判定逻辑整体换成 RSRP 栅格**。
- **顺带点出**：该文件 `analyze_coverage_gap:78` 目前**无任何 UI 调用**（孤儿代码），本功能即为它接线（但判定逻辑改为蜂窝 RSRP）。

## 6. 验收标准

每条均可判定、可测量。

| 编号 | 验收标准 |
|------|----------|
| A1 | 给定一组站点（含经纬度与频段）与一个制式，点击「覆盖诊断」后，插件在**不依赖后端、不落库**的前提下生成 RSRP 栅格图层，栅格值随站距衰减、随频段变化（同站点换频段/制式，栅格结果可观察变化）。 |
| A2 | 设定一个弱覆盖阈值后，能输出**弱覆盖区**图层；被判定为弱覆盖的栅格值均低于阈值（抽查 N 个栅格可复核），阈值调高/调低时弱覆盖区面积随之单调变化。 |
| A3 | 点击「生成建议站」后，每个弱覆盖聚类**恰好产出一条建议站记录**（聚类数与建议站条数一致），每条含：经度、纬度、需求评分、建议覆盖半径(km)、制式。 |
| A4 | 对任一建议站点击「采纳」后：该站**进入现有 `generated_sites`**，**出现在站点表中**，并在地图上以正式站符号渲染；`models/site.py` 侧与 UI 裸 dict 侧字段均被补齐（BOM/导出无缺项报错）。 |
| A5 | 对采纳站点执行 BOM 输出，能得到**该站的物料清单**（通过 `bill_of_materials()` / `_show_bom_dialog`），且 BOM 中含与所选制式对应的设备项。 |
| A6 | 全过程可在 **3 分钟内**由一个人从头演示到尾（诊断 → 建议 → 采纳 → BOM），无需切到其他系统、无需等待后端。 |
| A7 | 现有 7 步"现网补盲"演示路径不发生回归：新增步骤为**增量**，原有步骤行为与文案不受影响（除步骤编号顺延外）。 |

## 7. 明确"不做什么"（防范围蔓延）

1. **不接 MR / MDT / 路测数据**——弱覆盖判定只用 RSRP 栅格阈值法（用户已拍板）。
2. **不做后端落库**——不推送 M03 后端、不落库。原因：M03 后端 `DesignData` 无 `cables/pipeline/devices` 字段，数据库也没有 `cables/pipeline` 表（V1 只建 9 张表）。
3. **不做土建 / 杆塔工程量**——不新写基础浇筑、接地网、抱杆等工程量；BOM 沿用现有能力。
4. **不引入 S4 的物料字典**——不使用 `material_catalog.json`，材料清单以插件现有 BOM 为唯一来源。
5. **不改 FTTH 侧**——不修改 `ftth/` 既有行为；仅"参考" `coverage_gap.py` 的算法骨架与交互形态，判定逻辑另写。
6. **不修平台侧已知缺陷**（清单见下，均为"已知且本功能不触碰"）：
   - 拓扑引擎 `packages/m03-topology-engine/main.py` 的 `coverage_radius` **不参与 RSRP 计算**（L176/179/201 只用于网格外接半径与截断），RSRP 只吃 `frequency_band`（L302-304）；扇区多边形半径取模板默认值而非请求值（L361）。
   - M03 后端缺 `cables/pipeline` 表（V1 只 9 张表）——即"S3 覆盖率恒 0"的根因。
   - M03 前端 `views/CoverageAssessment.vue`（整页覆盖仿真）**未在 router 注册 = 死页**。

## 9. 制式维度是否纳入本次

**建议：纳入，且作为 P0 的输入参数（非 P2）。**

**理由（一句话）**：RSRP 计算（Okumura-Hata）本身就是频段/频率驱动的，覆盖半径随制式变是物理必然；`models/tech.py:TECH_BASELINE` 与「制式 → 覆盖半径/建议站间距」基线表已存在（见下），本次"边际成本"主要是让聚类粒度与建议覆盖半径读制式基线，而 `S1-#5实现Spec.md:69-70` 已规划"缺口聚类粒度随覆盖半径缩放"。

**作为输入的制式基线表（取自现有文档，示例值待校准）**：

| 制式 | 典型频段 | 覆盖半径(宏站) | 建议站间距 | 单站容量参考 | 塔桅/设备形态 |
|------|----------|----------------|------------|--------------|----------------|
| 4G LTE | 1.8–2.1 GHz | 1.0–3.0 km | 0.8–1.5 km | 中 | RRU + 天线 |
| 5G NR(Sub-6) | 3.5 GHz | 0.25–0.5 km | 0.2–0.4 km | 高 | AAU(有源天线) |
| 5G NR(mmWave) | 26/28 GHz | 0.1–0.2 km | 0.1–0.15 km | 极高 | 小微站/灯杆站 |
| 4G+5G 协同 | 多频 | 取短板(≈5G) | 取 5G 间距 | 叠加 | 多频天线/AAU |
