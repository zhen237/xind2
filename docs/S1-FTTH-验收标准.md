## 0. 为什么有这份文档（口径说明）

S1 官方需求设计文档 `docs/子赛题规格设计/2026-07-14-S1-需求设计文档.md` 与 `docs/S1-接口契约.md` 定义的是**基站/机房/管线参数化智能设计**业务域（RSRP 覆盖、Dijkstra 路网、DWG/DXF、经度范围 [73,135]、运城样例）。

但 S1 实测样例数据改用主办方提供的真实参考数据 `docs/真实数据/Plan_de_récolement/`（**JAD-MARJANE 数据集，摩洛哥 FTTH 竣工**），业务域为**光纤到户竣工交付物**。两者业务域完全不同，且数据域硬冲突（FTTH 经度 ≈ -8.5，不满足基站 Schema 的 [73,135] 范围校验）。

**决策（2026-08-03，用户拍板）**：S1 实际交付以 **FTTH 竣工智能辅助** 为准。本文件为该路线的**自洽验收基线**——官方需求文档的 AC-1~AC-6（基站）不适用本路线，以下 FTTH-AC-1~AC-8 为达标判定依据。

| 项 | 内容 |
|----|------|
| 数据源 | 8 图层 Shape（IMB/SITE/BOITE/CABLE/PTECH/INFRASTRUCTURE/ZNRO/ZPM）+ 13 lookup CSV + `Type boite.csv` + 官方 4 类交付物模板 + `图层表字段说明和数据校验规则.xlsx` |

## 2. 功能验收标准（AC）

| 编号 | 功能 | Given | When | Then |
|------|------|-------|------|------|
| **FTTH-AC-1** | 字段契约完整 | 加载 8 dbf | 解析字段 | 真实 dbf 字段全部覆盖（26/25/32/14/19/17/7/8），无缺漏、无多余需读字段 |
| **FTTH-AC-2** | 光交箱汇总 + 每箱明细 | 选定 Shape 目录 | 一键导出 | 生成 1 Sommaire + 每箱体明细 sheet；PBO=`Extremite`/`NB_LOGEMEN prises`，BPE=`Fenetrage`/`CAPACITE FO`（保真） |
| **FTTH-AC-3** | 四类竣工交付物 | 加载数据 | 导出 | Plans_de_Boie / Routes_Optiques / Plan_de_Baie / Synoptique 结构与官方模板一致（Tiroir/芯位/束管为占位，标注待数据源） |
| **FTTH-AC-4** | 拓扑真值连线 | CABLE 端点坐标齐全 | 前端渲染 | 120 条缆按真实 `ORIGINE→EXTREMITE` 端点连接（非占位）；3 站点根节点 |
| **FTTH-AC-5** | 行业标准数据自检 | 复用 S3 45 校验规则 | 跑校验 | 输出结构化报告；JAD 数据实测 **81.6% 通过**，抓真实缺陷（幽灵 PM / 越界 / 坐标漂移 / 空值） |
| **FTTH-AC-6** | 3D 可视化 | 浏览器打开 | Cesium 地球渲染 | 箱体点位 + 光缆连线（按 PM/类型分色）+ 3D 立柱 + 点击详情（箱体/缆/站点） |
| **FTTH-AC-7** | 正向智能规划 | 51 IMB 需求点（含户数+BPE 真值） | 算法反推 | 自动规划箱位/容量/路由；**聚类纯度 80.4%** 对比真实竣工；参数可调实时重算 |
| **FTTH-AC-8** | 前后端贯通 | QGIS 插件导出 | 前端 fetch JSON | Web 端展示竣工 + 规划，无需改造 Java 后端（静态 JSON 最短链路） |

## 3. 已知占位 / 外部依赖（非 bug）

| 占位项 | 占位内容 | 真实所需数据源 | 状态 |
|--------|----------|----------------|------|
| Routes_Optiques 首列 Tiroir | `TDI01-{后缀}` | 运营商熔接计划（盘位） | ❌ 待外部数据 |
| Plan_de_Baie 芯位逐格占用 | 1..24 序号 | 纤芯级熔接盘占用矩阵 | ❌ 待外部数据 |
| Synoptique 束管→缆段扇出 | 轮转默认 | 束管-缆段熔接计划 | ❌ 待外部数据 |

> 根因：8 个 Shape 图层不含"熔接计划/纤芯分配"。消除占位**必须用户提供运营商熔接计划数据**（独立 CSV/DB）。界面与文档中已明确标注为"待数据源"，避免视作未完成窟窿。
