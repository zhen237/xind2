# 通信基建数智化平台 · 零基础开发流程指南

> **适用对象**：没有任何编程经验的团队成员
> **目标**：跟着做，就能从「装软件」→「改代码」→「上传代码」，独立完成自己负责的那一块
> **预计耗时**：第一次搭建环境约 1~2 小时（大部分时间在等软件下载和安装）

---

## 先说清楚三件事（必读，2 分钟）

1. 我们做的是「通信基建数智化平台」，分 **5 个子任务（S1~S5）**，**每人负责一个，互不干扰**。你只管自己那一块。
2. 所有代码存在一个叫 **GitHub** 的网站上（网址 `https://github.com/zhen237/xind2`）。大家从那里下载、改完再传回去。
3. **你只改自己模块对应的文件夹，别碰别人的**，就不会出问题。

### 几个词先认识一下（看完就忘也没事，后面会反复用到）

| 词 | 大白话解释 |
|----|-----------|
| **仓库 / Repository** | 放所有代码的大仓库，在 GitHub 上。我们的仓库就是上面那个网址。 |
| **分支 / Branch** | 同一份代码可以同时有好几条「平行版本线」，各自改、互不打架。你只在你那条线上改。 |
| **提交 / Commit** | 把你改好的代码「存个档」，并写一句话说明改了啥。 |
| **推送 / Push** | 把你存档的代码上传到 GitHub，让队友也能看到。 |
| **拉取 / Pull** | 把队友上传的新代码下载到自己电脑上。 |
| **终端 / 命令行** | 一个可以打字执行命令的黑框框。我们用 Windows 自带的 **Git Bash**。 |
| **前端** | 你在浏览器里看到、能点的界面（网页那一层）。 |
| **后端** | 背后处理数据、算结果的「发动机」（看不见，但前端靠它干活）。 |

## 第 1 步：安装需要的软件

> 安装时一路点「下一步」即可。下面每个软件装完，都要**验证一下**，确保装对了再往下走。

### 1.1 Git（用来下载和上传代码）—— 必装
- 下载：https://git-scm.com/downloads （选 Windows 版）
- 安装：一路 Next，全部用默认选项
- **验证**：右键桌面 → 点 **Git Bash Here**，打开黑框框，输入：
  ```
  git --version
  ```
  看到 `git version 2.xx.x` 就成功了。
- 这个黑框框（Git Bash）以后就是我们输入所有命令的地方。

### 1.2 Node.js（前端界面需要它来运行）—— 必装
- 下载：https://nodejs.org （选 **LTS** 长期支持版，例如 22.x）
- **验证**：
  ```
  node -v
  ```
  看到 `v22.x.x` 就成功。

### 1.3 JDK 21（后端 Java 程序需要）—— 必装
- 下载：https://adoptium.net （选 **Temurin 21**，操作系统 Windows，架构 x64）
- 安装后**验证**：
  ```
  java -version
  ```
  **必须看到 `21.x.x`**（不是 8、不是 17，必须是 21，否则后端跑不起来）。

### 1.4 Maven（帮后端自动下载依赖、打包）—— 必装
- 下载：https://maven.apache.org/download.cgi （选 Binary zip 那个）
- 解压到一个简单路径，例如 `D:\maven\apache-maven-3.9.x`
- **验证**（用完整路径，把 x 换成你的版本号）：
  ```
  D:/maven/apache-maven-3.9.x/bin/mvn.cmd -v
  ```
  看到 Maven 版本 + Java 21 就成功。

### 1.5 VS Code（写代码的编辑器，像 Word 但专为代码设计）—— 必装
- 下载：https://code.visualstudio.com
- 安装时建议勾选「添加到右键菜单」
- 打开后，在左侧扩展图标里搜名字装两个免费插件：
  - `Vue Language Features (Volar)`
  - `Java Extension Pack`

### 1.6 Python 3.10（部分模块会用到）—— 看情况
- 下载：https://www.python.org/downloads/ （选 3.10.x）
- 安装时**务必勾选 "Add Python to PATH"**（这步漏了很麻烦）
- **验证**：
  ```
  python --version
  ```

### 1.7 QGIS（仅负责 S1 地图模块的同学需要）—— 仅 S1
- 下载：https://qgis.org/download/
- 其他模块的同学可以跳过这步。

## 第 2 步：把项目下载到自己的电脑（克隆）

1. 在电脑上找个放代码的文件夹，比如 `D:\homework`
2. 进入该文件夹，**右键 → Git Bash Here**，打开命令行
3. 输入（这会把整个项目下载下来，第一次比较慢）：
   ```
   git clone https://github.com/zhen237/xind2.git
   ```
4. 下载完会多出一个 `xind2` 文件夹，进入它：
   ```
   cd xind2
   ```

> **小贴士**：以后所有命令都在 Git Bash 里、并且**先 `cd` 进 `xind2` 目录**再执行。如果不确定自己在哪，输入 `pwd` 看当前路径。

---

## 第 3 步：拿到你要改的那条「分支」

1. 先问组长（或看分工文档）你该用哪条分支。例如负责 S1 的同学一般用 `feat/s1-parametric-design`。
2. 把分支下载并切换过去：
   ```
   git fetch origin
   git checkout feat/s1-parametric-design
   ```
   （把分支名换成你自己的）
3. **确认**你现在在正确的分支上：
   ```
   git branch
   ```
   当前所在分支前面会有一个 `*` 号。

> **推荐做法**：在自己分支上再开一条「个人小分支」，更安全，不会直接影响大家共用的线：
> ```
> git checkout -b feat/s1-你的名字
> ```

## 第 4 步：把项目跑起来（本地运行，看效果）

> 第一次运行要下载很多依赖，会比较慢，耐心等。

### 前端（你看到的网页界面）
```
cd packages/m03-bim-gis/frontend      # 换成你自己的模块文件夹
npm install                            # 第一次需要，下载依赖（慢，等几分钟）
npm run dev                            # 启动，终端会显示一个网址
```
浏览器打开终端里显示的那个网址（一般是 `http://localhost:xxxx`），就能看到项目界面。

### 后端（背后的发动机）
```
cd packages/m03-bim-gis/backend
D:/maven/apache-maven-3.9.x/bin/mvn.cmd spring-boot:run   # 启动后端
```
> 注意：后端需要连接数据库，第一次可能要**问组长要数据库密码和启动命令**，别自己瞎试。

**改完代码，保存文件（Ctrl+S），去浏览器刷新就能看到变化。**

## 第 5 步：开始改代码

1. 打开 **VS Code** → File → Open Folder → 选择 `xind2` 文件夹
2. 在左侧文件树里，找到**你负责的模块文件夹，只在里面改**：
   - S1 前端：`packages/m03-bim-gis/frontend/src`
   - S1 后端：`packages/m03-bim-gis/backend/src`
   - （其他模块路径问组长要）
3. 改的时候参考**同文件夹里已有的代码**，照着葫芦画瓢。
4. 保存（Ctrl+S），去浏览器看效果。

> ⚠️ **铁律**：**只改自己模块文件夹里的文件**。不要动 `shared`、`m01`、`m04`、`m06` 等别人负责的目录，否则会跟队友的代码打架（产生冲突）。

---

## 第 6 步：把改好的代码上传（提交 + 推送）

每次你改完一小段、想存档时，就做下面 4 步（在 Git Bash 里，且已 `cd` 进 `xind2`）：

**① 看看改了哪些文件**
```
git status
```
列出的红色文件名，就是你改过的。

**② 把要上传的文件「放进暂存区」**
```
git add 文件名            # 只加某一个文件（推荐，精确）
git add .                # 加所有改动（新手图省事可用，但要注意别加错文件）
```

**③ 存档并写说明**
```
git commit -m "改了S1覆盖报告的颜色"
```
说明要写清楚你干了啥，方便以后自己和队友看懂。

**④ 上传到 GitHub**
```
git push origin 你的分支名
```
例如：`git push origin feat/s1-你的名字`

看到终端显示 `... done` 或类似成功提示，就上传好了。去 GitHub 网页刷新，能看到你的提交记录。

## 第 7 步：常见问题处理

### 7.1 推送时一直转圈 / 报「证书」错误
这是本机网络加速器（Watt Toolkit）在拦截导致的。两种办法任选：
- **办法 A（推荐）**：把仓库地址换成「走 443 端口的 SSH 通道」：
  ```
  git remote set-url origin ssh://git@ssh.github.com:443/zhen237/xind2.git
  git push origin 你的分支名
  ```
- **办法 B**：关掉证书检查：
  ```
  git -c http.sslVerify=false push origin 你的分支名
  ```
都不行就找组长帮忙，别卡在这。

### 7.2 推送被拒绝，说「远程有你还没拥有的改动」
说明队友已经传了新代码，你本地落后了。先拉下来再推：
```
git pull origin 你的分支名
```
如果自动合并成功，再执行 `git push origin 你的分支名`。

### 7.3 出现「冲突」（Conflict）
**现象**：pull 或推送后，文件里出现 `<<<<<<<`、`=======`、`>>>>>>>` 这样的标记。
**意思**：你和队友改了同一处地方，Git 不知道该听谁的。
**解决步骤**：
1. 用 VS Code 打开有冲突的文件，搜索 `<<<<<<<`
2. 你会看到「上面的版本」和「下面的版本」，决定保留哪个（或各取所长手动合并成最终版）
3. **删掉** `<<<<<<<`、`=======`、`>>>>>>>` 这些标记行
4. 保存文件 → 执行：
   ```
   git add .
   git commit -m "解决冲突"
   git push origin 你的分支名
   ```

## 第 8 步：团队协作注意事项

1. **各改各的文件夹**：S1 只动 S1，S2 只动 S2。跨模块改动先群里说一声。
2. **开工先拉取**：每天开始写代码前，先 `git pull origin 你的分支名`，避免落后队友太多。
3. **小步快跑**：不要一次改一大堆再上传，改一点传一点，出问题好找原因。
4. **写清楚的提交说明**：「修复了 XX 按钮点不了」比「改了点东西」好一百倍。
5. **别用强制推送**：永远不要写 `git push --force`，那会把别人的代码冲掉。
6. **敏感信息别提交**：数据库密码、服务器密钥不要写进代码里传上去。
7. **不确定就问**：环境装不上、命令报错、不知道改哪，群里 @ 组长，别硬扛。
