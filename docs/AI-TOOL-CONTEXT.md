## 二、关键配置规范

### 2.1 环境变量配置

**所有敏感信息必须通过环境变量配置，禁止硬编码！**

| 环境变量 | 用途 | 默认值 |
|----------|------|--------|
| MYSQL_URL | 数据库连接URL | 必须配置 |
| MYSQL_USER | 数据库用户名 | 必须配置 |
| MYSQL_PASSWORD | 数据库密码 | 必须配置 |
| JWT_SECRET | JWT密钥（≥32字符） | 必须配置 |
| JWT_EXPIRATION | JWT过期时间（毫秒） | 604800000 |
| MINIO_ENDPOINT | MinIO地址 | 必须配置 |
| MINIO_ACCESS_KEY | MinIO访问密钥 | 必须配置 |
| MINIO_SECRET_KEY | MinIO秘密密钥 | 必须配置 |

**检查要点**: 
- 搜索 `password:` `secret:` `key:` 等关键词
- 检查是否有 `:default_value` 形式的硬编码默认值
- 确认 `.env.example` 文件存在且使用安全占位符

### 2.2 安全配置规范

**SecurityConfig必须遵循以下规则**:

1. **禁止** `anyRequest().permitAll()` — 必须明确指定公开接口
2. **必须**添加JWT认证过滤器
3. **公开接口**必须明确列举，其余接口需认证

**正确示例**:
```java
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/m01/auth/login").permitAll()
    .anyRequest().authenticated())
```

**错误示例**:
```java
.authorizeHttpRequests(auth -> auth
    .anyRequest().permitAll())  // ❌ 所有接口无需认证
```

### 2.3 postMessage安全规范

**禁止**使用 `*` 作为targetOrigin！

**正确示例**:
```javascript
const targetOrigin = currentUrl.value.substring(0, currentUrl.value.indexOf('/#'))
iframeRef.value.contentWindow.postMessage(data, targetOrigin)
```

**错误示例**:
```javascript
iframeRef.value.contentWindow.postMessage(data, '*')  // ❌ 跨域安全风险
```

## 五、更换AI工具错误重现分析

### 5.1 根本原因分析

更换AI工具后错误重现的根本原因在于以下几点：

| 根因 | 描述 | 影响 |
|------|------|------|
| **无持久化上下文** | AI工具没有项目记忆，每次更换后从零开始扫描 | 已修复问题被重新"发现" |
| **规范分散** | 项目规范分散在多个文档中，AI工具无法一次性获取 | 已有规范被忽视 |
| **缺乏检查清单** | 没有统一的检查清单指导AI工具进行系统性检查 | 检查范围不完整 |
| **无问题历史记录** | 已修复问题没有统一记录 | 重复修复同一问题 |
| **代码证据不足** | 修复后的代码没有明确的注释说明原因 | AI工具无法理解修复意图 |

### 5.2 预防措施

#### 5.2.1 建立不可变的项目约束文件

**本文件（AI-TOOL-CONTEXT.md）作为任何新AI工具的强制入口**，包含：
- 项目概述和技术架构
- 关键配置规范（安全配置、环境变量等）
- 代码质量检查清单
- 常见错误模式和搜索关键词
- 已修复问题列表

#### 5.2.2 维护已修复问题清单

在 `TASK-PRIORITY.md` 中记录所有已修复问题，包括：
- 问题描述
- 修复方式
- 涉及文件
- 修复日期

#### 5.2.3 将代码规范编码为可搜索模式

在本文件中定义明确的搜索关键词和错误模式，便于AI工具快速定位问题：

| 模式 | 搜索关键词 | 风险等级 |
|------|------------|----------|
| 硬编码密码 | `password:.*[^$]` | 🔴 高 |
| 硬编码密钥 | `secret:.*[^$]` | 🔴 高 |
| 权限绕过 | `anyRequest().permitAll()` | 🔴 高 |
| 跨域风险 | `targetOrigin.*\*` | 🔴 高 |

#### 5.2.4 代码注释说明修复意图

修复后的代码应添加注释说明修复原因和依据：

```java
// ⚠️ 安全修复：禁止使用anyRequest().permitAll()
// 必须明确指定公开接口，其余接口需认证
.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/m01/auth/login").permitAll()
    .anyRequest().authenticated())
```

#### 5.2.5 AI工具使用流程标准化

所有AI工具必须遵循以下检查流程：

```
1. 读取项目概述文档（PROJECT-OVERVIEW.md）
2. 读取本文件（AI-TOOL-CONTEXT.md）
3. 查看目录结构，了解项目组织方式
4. 读取开发规范（开发规范.md）
5. 搜索常见错误模式（本文件第四章）
6. 逐一验证问题，确认代码证据
7. 制定修复方案，记录修复原因
8. 执行修复，添加注释说明
9. 验证修复，确保无新问题引入
10. 更新TASK-PRIORITY.md记录
```

### 7.1 前置准备

使用AI工具进行代码检查前，必须：

1. **读取项目概述文档**: [PROJECT-OVERVIEW.md](PROJECT-OVERVIEW.md)
2. **读取本文件**: [AI-TOOL-CONTEXT.md](AI-TOOL-CONTEXT.md)

4. **读取开发规范**: [开发规范.md](开发规范.md)

### 7.2 检查流程

```
1. 读取项目上下文 → 2. 搜索常见错误模式 → 3. 逐一验证问题 → 4. 制定修复方案 → 5. 执行修复 → 6. 验证修复
```

### 7.3 问题分类标准

| 等级 | 标识 | 定义 | 处理时限 |
|------|------|------|----------|
| P0 | 🔴 紧急 | 安全漏洞、核心功能故障 | 24小时 |
| P1 | 🟠 重要 | 性能问题、用户体验问题 | 3天 |
| P2 | 🟡 一般 | 代码质量、文档问题 | 1周 |
| P3 | 🟢 低 | 技术债务、远期改进 | 按需安排 |

### 7.4 修复验证标准

修复完成后必须验证：

1. **代码编译通过**（后端）
2. **构建成功**（前端）
3. **单元测试通过**（如有）
4. **功能验证**（手动或自动化）
5. **无新问题引入**（回归检查）
