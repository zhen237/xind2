## 1. 一句话目标

面向通信基建工程「设计 → 审查 → 施工指令 → 施工监管」全流程，构建一套**多赛题协同、数据贯通、可在线演示**的数智化平台，参加挑战杯「揭榜挂帅」专项赛并交付可验证的成果。

## 3. 五个子赛题（范围核心）

平台由 5 个官方子赛题构成，覆盖通信基建工程全链路：

| 赛题 | 名称 | 核心产出 | 负责模块（端口） |
|------|------|----------|------------------|
| **S1** | GIS 智能辅助设计 | 基站/FTTH 参数化设计、拓扑、三维可视化、竣工交付物 | qgis-plugin + m03-bim-gis(8083/5174) + m03-topology-engine |
| **S2** | 多源异构工程数据融合 | DWG/DXF→GeoJSON、坐标系转换、CAD+GIS 融合 | s2-cad-fusion(8082/5182) |
| **S3** | 基于行业标准的设计智能审查 | 5 类 25+ 规则精确计算、违规清单、3D 标注、报告 | s3-review-engine(8089/5189) |
| **S4** | 设计成果向施工指令自动转化（BOM） | 设备-物料映射、辅材/线缆估算、Excel 导出 | s4-bom-transform(8090/5190) |
| **S5** | 隐蔽工程影像分析与数字化验真 | YOLOv8/SAM 影像分析、设计-施工对比、防篡改档案 | m07-cv-engine(8088)+m05-twin-ops(8085)+s5-construction-monitor(8091/5191) |

**共享归口**（不归属任何赛题，所有人通过 REST API 调用）：`m01-auth`(8080)、`m06-portal`(5173)、`shared`、`screen`(8087)。

**全链路数据流**：
```
S2(CAD融合) → S1(设计) → S3(审查) → S4(BOM施工指令) → S5(施工监管/验真)
                                    ↘ S5 检测结果反馈 S3 验收
```

## 5. 范围边界

### 5.1 做什么
- 5 个子赛题对应的 11 个业务模块 + 4 个共享基础设施模块。
- 全链路「设计→审查→指令→监管」的数据贯通与门户聚合（m06-portal iframe 接入）。
- 本地可运行 + S1 在线演示（GitHub Pages，虚拟数据）。

### 5.2 不做什么（明确排除）
- ❌ 不搭建公有云生产级部署（演示在本机/单台测试机即可）。
- ❌ 不做运营级 SaaS / 多租户。
- ❌ 不使用真实涉密工程数据——统一用主办方样例 + AI 生成模拟数据（如 S5 隐蔽工程影像、S2 运城 CAD）。
- ❌ 不自行实现跨赛题的私有数据传输通道（只走 REST API 契约）。
