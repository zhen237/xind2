## 五、核心亮点话术（答辩时逐条背熟）

1. **"我们交付的不是一张物料表，而是完整的施工指令包"** —— BOM + 工序 + 纤芯 + Excel，四件套
2. **"规则引擎而不是硬编码"** —— 物料映射、辅材推算、线缆估算都是规则/公式驱动，换场景不用改代码
3. **"线缆误差 <15% 有公式背书"** —— Haversine 3D 距离 + 1.2 安全系数 + 4 种计算方式
4. **"审查闸门"** —— 设计未过审，BOM 生成被拦截（闭合 FR-10），体现对质量的尊重
5. **"契约先行 + 双数据源"** —— mock 模式开发，real 模式联调，接口好了改配置就行，不阻塞团队
6. **"8 个验收用例全覆盖，AC-1 到 AC-8 全部实测通过"** —— 工程化交付，不是 demo 级玩具

## 六、评委 Q&A 预判（15 问，附标准答案）

### 技术类
**Q1：为什么用 Python 引擎而不是 Java 全做完？**
A：① Excel 生成（openpyxl）和地理距离计算在 Python 生态最成熟；② 与 S2/S3 赛题统一 Python 3.10 技术栈，团队可互相 review；③ 规则迭代快，演示时改规则不用重新编译。

**Q2：线缆估算误差 <15% 怎么保证？**
A：Haversine 公式算球面 3D 距离（含高度差），再乘 1.2 施工系数；提供 4 种计算方式（直线/水平/3D/路由），真实数据接入后可对标实际布线验证。

**Q3：物料编码库只有 12 条映射，够用吗？**
A：诚实回答 + 转守为攻：当前是样例题库，但映射是**规则驱动的可扩展结构**（material_catalog.json），真实工程物料几百种，接入时按同样的 JSON 结构扩充即可；漏项率我们用人工对照清单核验，目标是 <2%。

**Q4：审查不通过时系统怎么处理？**
A：Java 后端有审查闸门——从 S3 拉审查结果，`isApproved=false` 直接拦截，返回 `S4_REVIEW_NOT_APPROVED`，设计重审通过前不会生成 BOM。

**Q5：S1 返回的字段和你们 mock 的不一样怎么办？**
A：引擎有 `_normalize_device()` 归一化层，能容忍字段名/结构差异；大结构差异在联调清单里有逐项核对表，按表适配即可。

**Q6：BOM 生成是同步还是异步？耗时瓶颈在哪？**
A：异步——前端点生成立即返回 taskId，后台执行。耗时主要是引擎计算 + Excel 写盘，目前 8 秒级；实测全流程（含落库）远低于 1 分钟。

### 架构/协作类
**Q7：你们怎么和 S1/S3/S5 衔接？**
A：严格走 REST API，不直连库。S1 设计清单（I3 契约）→ S3 审查结果 → S4 生成 → S5 验真推送（I4 契约）。dev-proxy 就是真实接口的替身，路径和字段都按团队契约模拟。

**Q8：如果 S1/S3 还没做好，你怎么验收？**
A：契约先行 + mock 驱动。mock 数据完全按契约结构构造，所以 S1 做好后我们只换数据源，业务逻辑一行不改。

**Q9：为什么不用 Docker？**
A：团队统一约定本地手动启动，端口已固化（8090/8100/5190），演示机环境已就绪，开箱即用。

### 业务/指标类
**Q10：1 分钟是怎么测的？**
A：benchmark_bom.py 脚本端到端计时：从调 /api/s4/bom/generate 到 BOM 完整落库。可以现场再跑一次证明。

**Q11：辅材漏项率 <2% 怎么验证？**
A：人工核验——拿生成的三场景 BOM 与通信工程辅材标准对照（天线安装套件、RRU 防水套件、接地、标签、扎带等），目前零漏项；接入真实工程后可继续按此方法抽检。

**Q12：工序和纤芯分配是谁的需求？**
A：需求文档 FR 要求"BOM 等施工指令"，我们理解施工指令不止物料，还包括怎么干（工序）和光纤怎么分（纤芯），所以补全了这两块，形成完整施工指令包。

**Q13：数据是虚拟的，能说明问题吗？**
A：输入数据是模拟的（标注清楚），但**规则是真实的**——物料映射、估算公式、工序模板都基于通信工程标准；且双数据源已留好，真实数据接入后引擎行为不变。这正好说明我们"规则与数据解耦"的设计。

### 项目类
**Q14：Java 后端跑起来过吗？**
A：（如实 + 积极）核心链路当前由 dev-proxy 承担并全量实测通过；Java 侧已完成 S1S3/S5 对接代码，等答辩环境装好 JDK17 + Maven 即可编译验证，联调清单里已列为待办。**建议：答辩前装好并跑通，这一题必须解决。**

**Q15：团队里你的模块和别人的重合吗？**
A：不重合。S2/S3/S5 各有明确边界，我用 s4_ 前缀独立交付；跨赛题只通过 REST 契约交互，模块可独立验收、独立演示。
