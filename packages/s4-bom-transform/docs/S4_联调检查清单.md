# S4 接真实数据联调检查清单

> 用途：S1/S3/S5 真实接口就绪后的对接操作手册。
> 引擎（Python）与 dev-proxy 均已内置 **mock / real 双数据源**，联调日无需改代码，只改配置。

## 一、数据源切换配置（3 个服务各管各的）

### 1. Python 引擎（8100）
`engine/.env` 或环境变量：

```
S4_DATA_SOURCE=real
S4_S1_BASE_URL=http://<S1服务地址>:<端口>
```

切换后引擎的 `GET {S1_BASE_URL}/api/s1/design/tasks/{designTaskId}` 拉取真实设计清单。

### 2. dev-proxy（8090）
启动前设置环境变量：

```
S4_DATA_SOURCE=real
S1_REAL_URL=http://<S1服务地址>:<端口>
```

S1 详情、S3 审查结果自动转发真实接口；请求失败会**降级 mock + 打印 WARN**，保证联调期页面可用。

### 3. Java 后端（8090，当前未运行）
`application.yml`：

```yaml
s4:
  integration:
    data-source: real
    s1-url: http://<S1服务地址>:<端口>
    s3-url: http://<S3服务地址>:<端口>
    s5-url: http://<S5服务地址>:<端口>
    auth-token: "<m01-auth JWT>"
```

## 二、联调当天按顺序核对

| # | 检查项 | 通过标准 | 备注 |
|---|--------|----------|------|
| 1 | S1 接口可达 | `curl http://<S1>/api/s1/design/tasks/D001` 返回 200 | 确认字段含 `data.devices[]` |
| 2 | 字段契约对齐 | 引擎日志无 `归一化` 告警 | 差异由 `_normalize_device()` 兜底，大结构差异需适配 |
| 3 | S3 审查闸门 | 未审查通过的设计被拦截（S4 返回 `S4_REVIEW_NOT_APPROVED`） | Java 侧 `S1S3DataService.isApproved()`；审查服务不可达时降级放行 |
| 4 | BOM 生成 | D001 真实数据 → done，物料条数与设计清单匹配 | mock 基准：100 条 / 26 工序 / 33 纤芯 |
| 5 | S5 推送 | `GET <S5>/api/s5/verify/tasks` 能看到新 BOM 记录 | Java 侧 `S5NotifyService`，旁路失败不阻断 |
| 6 | JWT 鉴权 | 带 token 调用全部通过 | m01-auth 统一发放 |
